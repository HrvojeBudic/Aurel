# P1.4 — Research Alignment Notes

**Phase:** P1.4.0  
**Purpose:** Map research-integrated concepts into P1.4 without overbuilding them  
**Companion:** [P1.4 Scope Contract](P1.4_IDENTITY_AUTONOMY_SCOPE_CONTRACT.md), [P1.4 Agent Trust Constitution](P1.4_AGENT_TRUST_CONSTITUTION.md)

---

## 1. Agent Identity

Research and industry literature often conflate:

- **Model identity** — which LLM or weights are loaded
- **Agent identity** — who the agent is, its role, and Operator relationship
- **Workload identity** — runtime instance, session, or task context
- **Delegated authority** — what an agent may do on behalf of a principal

P1.4 introduces **Agent Identity Card** (P1.4.7) as a placeholder trust surface. The full **agent identity mesh** (delegation, non-repudiation, cross-agent trust) is deferred to **P1.8**.

P1.4.0 establishes: identity is not policy; persona is not authority.

---

## 2. Autonomy Measurement

Two distinct concepts:

- **Declared autonomy** — Operator-selected level with scope, TTL, and boundaries (P1.4.8)
- **Measured autonomy** — observed capability surface from runtime/config inspection (P1.4.9, P1.4.12)

Mismatch between declared and measured autonomy is a governance signal, not a self-correction trigger. Aurel cannot self-escalate to resolve mismatch.

Code/config inspection for autonomy scoring is implemented in P1.4.9 and P1.4.12 — not in P1.4.0.

---

## 3. Cognitive Architecture

Identity, memory, action, and decision loops are **separate layers**:

| Layer | Primary phase | P1.4 role |
|-------|---------------|-----------|
| Identity / autonomy | P1.4 | Scope, constitution, stubs |
| Memory graph | P3 Mneme | Forward hook only |
| Action / execution | P0.x runtime, P6+ Tool Bus | Unchanged by P1.4.0 |
| Decision / planning | P0.x entity, repo agent | Unchanged by P1.4.0 |

P1.4 handles identity and autonomy boundaries only. Full persistent memory architecture is P3.

---

## 4. Persistent Agent / System 3

Research on persistent agents and "System 3" meta-cognition suggests long-horizon self-models and drift monitoring.

P1.4 prepares:

- **Self-Model v0.1** (P1.4.6) — bounded self-description
- **Meta-Cognitive Drift Signals** (P1.4.18) — divergence detection

Full persistent meta-cognition, world-model integration, and autonomous self-improvement are **out of scope** for P1.4.

---

## 5. World Models

P1.4 does **not** implement Noesis (prediction, simulation, evolution).

| Phase | Responsibility |
|-------|----------------|
| P10/P11 | Noesis — world models, simulation |
| P21 | Verified Autonomy — evidence-backed autonomy |
| P1.4 | Capability honesty; self-model boundaries only |

P1.4 must not claim world-model or predictive capabilities. Self-model in P1.4.6 describes **known limits**, not simulated futures.

---

## 6. Governance

P1.4 introduces the **constitutional floor** (P1.4.11) — minimum laws no mode or profile may violate.

Full governance stack is layered:

| Phase | Component |
|-------|-----------|
| P1.6 | Policy cards and behavioral contracts |
| P1.7 | Path governance engine |
| P6 | Custos v2 and expanded tool governance |

P1.4 governance stubs (`governance/`, `heretic/`) are placeholders. Persona cannot override policy.

---

## 7. Evaluation

P1.4 introduces **capability honesty** — distinguishing planned, implemented, verified, and unavailable capabilities.

**P1.5 Evaluation Mirror** implements evidence collection and verified capability claims. P1.4.0 does not implement evaluation infrastructure; it defines the honesty requirement that P1.5 will enforce.

Capability claims require evidence or must be marked unverified.

---

## 8. Provenance and Disclosure

P1.4 adds **posture only**:

- Serious actions must be traceable
- No external disclosure without policy allowance (constitutional floor)

**P1.9** implements Output Passport, provenance chains, and disclosure engine. P1.4 forward-hooks traceability requirements without building P1.9 components.
