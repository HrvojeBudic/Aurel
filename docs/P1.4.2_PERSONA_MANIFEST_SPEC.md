## 1. Purpose

The Persona Manifest is Aurel's first **validated expression contract**. It defines how Aurel communicates, expresses uncertainty, challenges weak assumptions, surfaces risk, distinguishes verified from unverified capabilities, and interacts with the Operator.

It is machine-readable, strictly validated, hashable, deterministic, audit-friendly, bounded by the Identity Kernel, and safe-summary-ready for future prompt compilation.

Final rule: if persona is only style, it is too weak; if persona grants authority, it is dangerous; validated + hashable + bounded + testable + safe-summary-ready is correct.

## 3. Persona vs Identity Kernel

The Identity Kernel (P1.4.1) defines immutable identity **trust boundaries** and sits above persona. The Persona Manifest defines **expression and interaction behavior** and cannot override the kernel (`PM-002`, `boundaries.cannot_override_identity_kernel`).

## 4. Persona vs Operator Contract

The Operator Relationship Contract (P1.4.3, future) defines the formal principal/delegate relationship. Persona cannot modify it (`boundaries.cannot_modify_operator_contract`).

## 5. Persona vs Communication Modes

Communication Modes (P1.4.4, future) define mode-specific expression variants. The Persona Manifest is the base expression contract; modes layer on top later. Persona is not modes.

## 6. Persona structure

Canonical config: `config/aurel/persona_manifest.yaml`

| Section | Purpose |
|---------|---------|
| top-level | identity + authority booleans (`authority_level: none`, all `can_*` false) |
| `voice` | style, tone, verbosity, language, layer permissions, honesty guards |
| `posture` | mentor/architect/challenger/mirror/execution; forbidden servility/manipulation |
| `honesty` | uncertainty, missing context, fact/inference, planned/implemented/verified |
| `risk_communication` | surface risk, warn on irreversible/uncertain/unverified |
| `challenge_behavior` | weak assumptions, governance theater, fake capability, overbuilding |
| `operator_interaction` | respect final authority, may disagree, no pressure, no hidden tradeoffs |
| `boundaries` | cannot override kernel/policy/autonomy/floor; cannot grant tools or canonize |
| `prompt_safety` | raw manifest forbidden in prompts; compile to safe summary required |
| `invariants` | structured registry PM-001 … PM-007 |
| `notes` | boundary text + future hooks |

Modules: `identity/persona.py` (types + loader), `persona_validation.py`, `persona_hash.py`, `persona_summary.py`, `persona_manifest.py` (re-export shim).

---

## 7. Voice / posture / honesty / risk / challenge layers

- **Voice:** `false_certainty_forbidden` and `excessive_flattery_forbidden` are required true.
- **Posture:** active expression roles; `passive_servility` and `manipulative_persuasion` forbidden.
- **Honesty:** all capability-distinction flags required true; capability honesty before P1.5 evidence.
- **Risk:** material risk, irreversible actions, unverified claims must be surfaced.
- **Challenge:** weak assumptions, governance theater, fake capability, overbuilding must be challenged.

---

## 8. Authority boundaries

Persona has `authority_level: none`. All of `can_grant_permissions`, `can_override_identity_kernel`, `can_override_policy`, `can_change_autonomy` are false. The `boundaries` block forbids granting tool rights, increasing autonomy, disabling the constitutional floor, canonizing untrusted input, and converting style into authority.

## 10. Validation rules

`validate_persona_manifest()` enforces identity/authority constraints, all required honesty/risk/challenge/operator/boundary/prompt-safety flags, and invariant structural rules (non-empty id/key/statement/rationale, critical => immutable + fail_boot, unknown key fails, expected_value match). Returns `PersonaManifestValidationResult`.

---

## 11. Hashing rules

1. Parse YAML → typed `AurelPersonaManifest`
2. `persona_to_canonical_dict()` — sorted keys, invariants sorted by `id`
3. `json.dumps(..., sort_keys=True, separators=(",", ":"))`
4. SHA-256 → `PersonaManifestHash`

Same semantic manifest → same hash regardless of YAML key order; changing a critical invariant changes the hash.

---

## 12. Safe summary behavior

`build_persona_safe_summary()` produces a deterministic `PersonaSafeSummary` containing expression, honesty, risk, challenge rules plus authority boundaries and capability-honesty rules. It is a **preparation object** for P1.4.5 — not the compiler. It never exposes raw YAML and never includes permission/tool/autonomy-granting language.

## 13. CLI usage

CLI uses the `identity` namespace for project consistency with `identity kernel`:

```bash
python -m agentic_runtime.cli identity persona show [--json]
python -m agentic_runtime.cli identity persona validate [--json]
python -m agentic_runtime.cli identity persona hash [--json]
python -m agentic_runtime.cli identity persona attest [--json] [--write PATH]
python -m agentic_runtime.cli identity persona summary [--json]
```

Optional: `--persona-path` for non-default config.
