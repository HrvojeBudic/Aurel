**Status:** Implemented

## 1. Purpose

The Identity Prompt Context Compiler is Aurel's **first identity-aware prompt compilation layer**. It consumes validated source objects from P1.4.1–P1.4.4 and compiles them into a safe, inspectable, hash-bound `IdentityPromptContext` with deterministic rendering and attestation.

Prompt context may guide model reasoning and expression. Runtime governance still enforces action.

---

## 2. Non-goals

Not implemented in this patch:

- Actual LLM calls or model provider integration
- Atlas router, tool execution, Autonomy Scale, Governance Profiles
- Policy Cards, Path Governance, Heretic Sandbox
- Self-Model (P1.4.6), Agent Identity Card (P1.4.7)
- Memory writes, world model, runtime action enforcement

---

## 3. Source objects

The compiler consumes:

| Source | Patch | Loader |
|--------|-------|--------|
| Identity Kernel | P1.4.1 | `load_identity_kernel()` |
| Persona Manifest | P1.4.2 | `load_persona_manifest()` |
| Operator Relationship Contract | P1.4.3 | `load_operator_contract()` |
| Communication Mode Registry | P1.4.4 | `load_communication_mode_registry()` |
| Compiler Policy | P1.4.5 | `load_identity_prompt_compiler_policy()` |
| Selected mode | P1.4.4 | `get_communication_mode()` |

Safe summaries from P1.4.2–P1.4.4 are used; raw YAML is never injected.

---

## 4. Source dominance order

1. Identity Kernel
2. Operator Relationship Contract
3. Persona Manifest boundaries
4. Communication Mode boundaries
5. Selected mode output shaping

Lower-layer contradictions fail compilation.

---

## 5. Raw config firewall

- Compiler policy requires `raw_yaml_in_prompt_forbidden: true`
- Renderer never dumps YAML or full config
- Prompt sections are compiled from typed objects and safe summaries only

---

## 6. Compiler policy

Canonical config: `config/aurel/identity_prompt_compiler.yaml`

Root key: `identity_prompt_compiler`

Includes: `source_requirements`, `safety`, `dominance`, `prompt_sections`, IPC-001–IPC-008 invariants.

Validator: `validate_identity_prompt_compiler_policy()`

---

## 7. IdentityPromptContext structure

Frozen dataclass with:

- `schema_version`, `compiler_version`, `agent_name`, `agent_class`, `selected_mode`
- `source_bundle` (five source hashes + selected mode)
- Eight section tuples (see §8)

---

## 8. Prompt sections

| Section | Content |
|---------|---------|
| `agent_identity` | Agent name, class, local-first posture, identity ≠ authority |
| `operator_relationship` | Operator final authority, challenge/refusal, non-manipulation |
| `persona_expression` | Voice, honesty, risk, challenge rules |
| `active_mode` | Mode purpose, posture, output/challenge/risk emphasis; HERETIC candidate-only |
| `authority_boundaries` | No self-escalation, tool/action/autonomy/policy/memory/canonization grants |
| `capability_honesty` | Planned vs implemented vs verified; no unverified claims |
| `non_goals` | Prompt context does not authorize runtime actions |
| `source_integrity` | Five hashes, selected mode, compiler version |

---

## 9. Contradiction detection

At least 28 contradiction classes including:

- Invalid sources (kernel, persona, operator, modes, policy)
- Unknown selected mode
- Self-escalation, Aurel final authority, persona permission grants
- Mode permission/autonomy/execution/canonization violations
- HERETIC side-effect/modification violations
- Compiler policy raw-YAML or missing-hash violations
- Post-build missing required content

Critical contradictions set `valid=False`, `context=None`, `context_hash=None`.

---

## 10. Context validation

`validate_identity_prompt_context()` checks section-specific required content including Operator final authority, no-self-escalation, capability honesty, authority boundary statements, source hashes, and HERETIC-specific rules.

---

## 11. Hashing rules

- Canonical dict → JSON (`sort_keys=True`, compact separators) → SHA-256
- Context hash includes all sections, source bundle, selected mode, compiler version
- Policy hash covers full compiler policy document

Functions: `compute_identity_prompt_context_hash()`, `compute_identity_prompt_compiler_policy_hash()`

---

## 12. Renderer behavior

`render_identity_prompt_context(context) -> str`

Deterministic markdown-style fragment with ordered section headers. No raw YAML, no secrets, no side effects.

---

## 13. Attestation behavior

`build_identity_prompt_attestation()` / `write_identity_prompt_attestation()`

Explicit write only (CLI `--write` or test invocation). Default path suggestion: `.runtime/aurel/identity_prompt_context_attestation.json`

---

## 14. CLI usage

Under `identity context` namespace (required `--mode`):

```bash
python -m agentic_runtime.cli identity context compile --mode DEPLOY --json
python -m agentic_runtime.cli identity context validate --mode FOCUS
python -m agentic_runtime.cli identity context hash --mode SHADOW
python -m agentic_runtime.cli identity context render --mode DEPLOY
python -m agentic_runtime.cli identity context attest --mode HERETIC --json
```

Path overrides: `--kernel-path`, `--persona-path`, `--operator-path`, `--modes-path`, `--compiler-path`
