# P1.5.11B Capability Evidence Trace / Context Binding

Date: 2026-06-22

## Purpose

P1.5.11B upgrades Golden Thread A capability evidence so verified capability evidence is trace-bound, source-hash-checked, evidence-bound, verifier-bound, limitation-bound, context-aware, and evidence-strength-gated.

The patch closes the failure class:

```text
The output passed, but Aurel acted with wrong, insufficient, unsafe or unverifiable context.
```

## What Changed From P1.5.11A

P1.5.11A proved:

```text
verified capability requires trace + evidence + verifier + limitations
```

P1.5.11B now also requires:

```text
source_event_hash matching TraceEventRef.event_hash
evidence_strength in strong | verified
safe or adequate context
explicit context limitation for partial context
```

## New Objects

- `ContextBindingRef`
- `ContextAdequacyStatus`
- `ContextAdequacyReport`
- `EvidenceStrengthLevel`

## Updated Objects

`CapabilityEvidenceRecord` now stores:

- `source_event_hash`
- `context_binding_ref`
- `context_adequacy_ref`
- `evidence_strength`

`GoldenThreadAResult` now exposes:

- `context_binding_ref`
- `context_adequacy_ref`
- `source_event_hash`
- `evidence_strength`
- `capability_evidence_status`

## New Invariants

- Verified capability evidence requires `source_event_hash`.
- `source_event_hash` must match `source_trace_event_ref.event_hash`.
- Verified capability evidence requires evidence strength `strong` or `verified`.
- Weak, moderate and none evidence cannot produce verified capability evidence.
- Unsafe context blocks verified capability evidence.
- Insufficient context blocks verified capability evidence.
- Partial context requires an explicit context limitation.
- Adequacy score is dashboard metadata and cannot override unsafe or insufficient status.
- Projection-only sources cannot verify capability evidence.

## Updated Golden Thread A

Golden Thread A now runs:

```text
Intent
→ ContextBindingRef
→ Policy decision stub
→ Lease stub
→ Stub execution
→ canonical TraceEvent
→ EvidenceRef
→ VerifierResult
→ ContextAdequacyReport
→ CapabilityEvidenceRecord v2
```

The demo uses:

- `ContextAdequacyReport.status = adequate`
- `EvidenceStrengthLevel = verified`
- `VerifierResult.status = pass`
- non-empty verifier limitations
- non-empty capability limitations
- canonical source event hash from `TraceEventRef.event_hash`

## Explicit Out Of Scope

P1.5.11B does not implement full AurelBrain, full AurelContextPacket, full AurelFlow Runtime, real AurelExec, real ExecutionLease, ObjectRef plane, workflow scheduling, approval pause, retry/recovery, tool execution, shell execution, LLM execution, full Ledger migration, full Mneme lifecycle, Noesis, SoulIntegrityReport, full OperatorFeedback, CapabilityClaimRegistry, or EvaluationCase extraction.

## Seal Criteria

P1.5.11B is sealed when verified capability evidence is:

- canonical-trace-bound
- source-hash-checked
- evidence-bound
- verifier-bound
- limitation-bound
- context-aware

And when these states are impossible:

- verified capability with no trace
- verified capability with mismatched trace hash
- verified capability with no evidence
- verified capability with failed verifier
- verified capability with no limitations
- verified capability under unsafe context
- verified capability under insufficient context
- verified capability from projection-only source
- verified capability from weak evidence
