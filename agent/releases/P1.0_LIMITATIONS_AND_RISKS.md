# P1.0 Limitations and Risks

Honest constraints for the Runtime Alpha release. Do not overclaim beyond this list.

## Planning and patching

- **LLM plans but does not synthesize patches yet.** `LLMRepoPlanner` produces structured `RepoTaskPlan` JSON only; execution uses existing deterministic patch paths.
- **Patch synthesis remains deterministic and narrow.** Supported transformations are intentionally small (e.g. bounded string replace); not a general coding agent.
- **Hybrid planner falls back to deterministic** when LLM output is invalid or unavailable; fallback is recorded, not silent.

## Sandbox and security

- **`restricted_local` is not a production security sandbox.** It limits paths and exec policy but runs on the host filesystem.
- **`unsafe_local_demo` must never be used for mutating production tasks.**
- **Hard sandbox requires bubblewrap or Docker** on the apply host. Without them, `--apply` degrades to `restricted_local` with warnings.
- **Bubblewrap apply path may diverge from harness success criteria** on some hosts: independent post-harness tests can pass while in-agent `test_result` reports failure under bwrap (documented in P1.0 seal report). Scenario tests default to `restricted_local` and pass in CI/pytest.

## Providers and credentials

- **Real providers are optional and unverified without credentials/config.** OpenAI, Anthropic, and Ollama adapters exist but integration tests are skipped offline.
- **Mock provider is the default** for tests and demos; no API keys required for seal verification.

## Verification and release integrity

- **CI must pass on a clean checkout** before a public **PASS** claim. Workflow targets Python 3.11 and 3.12; local seal used 3.12.3 only at time of P1.0.1.
- **Python 3.11 / 3.12 are verified targets** per `pyproject.toml` classifiers and CI matrix. **Python 3.13 is not guaranteed** unless added to CI.
- **No baseline git commit existed** before P1.0.1; GitHub Actions had not run.

## Tooling and scope boundaries

- **No network tools** — no governed HTTP/fetch execution surface.
- **No delete tools** — filesystem deletes are not exposed as tools.
- **No git commit or git push tools** — read-only git status/diff only.
- **No UI** — CLI and JSON output only.
- **No multi-agent orchestration** — single repository agent loop.
- **No memory canonization** — Praxis produces candidates with promotion gates; nothing auto-promotes to verified memory.

## Operational risks

| Risk | Mitigation |
|------|------------|
| Operator assumes alpha equals production security | Read `docs/DEPLOYMENT.md`; install bwrap/docker for apply |
| LLM plan mistaken for executable authority | `RepoPlanValidator` + runtime pipeline unchanged |
| Evidence paths leak host layout | `write_evidence` redacts to repo id; P1 evidence uses relative paths only |
| Timeout tests flaky in nested sandboxes | `requires_subprocess` skip in `conftest.py` |

## Seal status implication

These limitations support a **PRE-SEAL** or **PASS-with-caveats** decision only after full CI green. They do **not** justify weakening tests or faking readiness.
