# P1.0 Next Cycle Roadmap

Recommended phases after Runtime Alpha seal hygiene (P1.0.1). Ordered by dependency and risk reduction.

## P1.1 — LLM Patch Synthesis Candidate

**Goal:** Allow LLM-proposed patch *candidates* that still pass through governed validation, approval, sandbox, and verifier — no vendor tool-calling.

- Structured patch proposal schema separate from executable commands
- Fail-closed validation before `patch_file` execution
- Mock-provider tests offline; optional real-provider smoke behind flags

## P1.2 — Multi-Step Repair Exercise

**Goal:** Expand `RepairLoop` with governed multi-step repair scenarios beyond single replace.

- Additional demo scenarios with honest failure reporting
- Bounded attempt budgets and trace receipts per repair step
- Tests proving no bypass of approval or sandbox between steps

## P1.3 — Provider Integration Hardening

**Goal:** Make optional providers operable and testable without weakening offline CI.

- Credential discovery documentation and health checks
- Retry/timeout discipline on stdlib HTTP adapters
- CI-friendly contract tests with recorded fixtures (no live keys in CI)

## P1.4 — Sandbox Backend Reality Upgrade

**Goal:** Close the gap between CLI auto-selected hard sandboxes and harness success criteria.

- Reconcile in-agent test execution under bubblewrap/docker with harness final status
- Document and test apply-path smoke on Linux CI with bwrap installed
- Clear operator signals when soft fallback is active

## P1.5 — Trace / Praxis Promotion Court

**Goal:** Governed promotion from candidates toward durable memory — still not auto-canonization.

- Promotion court workflow with explicit operator/decision records
- Trace-linked evidence bundles for promotion decisions
- Reflex bridge remains proposal-only

## P2.0 — Operator Console / Command Center

**Goal:** Human-facing control plane for approvals, status, and trace inspection.

- Not started in P1.0; CLI remains canonical until P2.0
- HITL console integration with existing approval contracts
- No weakening of runtime authority boundaries
