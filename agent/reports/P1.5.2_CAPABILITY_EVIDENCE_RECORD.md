# P1.5.2 — Capability Evidence Record

**Date:** 2026-06-21  
**Status:** COMPLETE (READY)  
**Next module:** P1.5.3 — Evaluation Subject Registry

## 1. Summary

P1.5.2 creates the bridge between evaluation results and future capability claim verification. `EvaluationResult` and `EvaluationResultSet` map to `CapabilityEvidenceRecord` with categorical status and strength. Evidence records are admissible containers — **USABLE is not VERIFIED**.

**Core law:**

```
EvaluationResult is not capability verification.
EvaluationResult can become part of CapabilityEvidenceRecord.
CapabilityEvidenceRecord can support a capability claim later.
CapabilityEvidenceRecord does not verify capability by itself.
```

**Deliverables:**

- `src/agentic_runtime/evaluation/capability_evidence.py`
- CLI: `evaluation capability-evidence status/examples --json`

## 5. Capability evidence model

```
EvaluationResult / EvaluationResultSet
  → CapabilityEvidenceRecord
  → later Evidence-to-Claim Binding (P1.5.7)
  → later Capability Verification Levels (P1.5.15)
  → later CapabilityClaimDecision impact
```

Forbidden chain: `EvaluationResult PASSED → Capability VERIFIED`

`CapabilityEvidenceRecord` fields: `evidence_id`, `capability_id`, `claim_id`, `kind`, `status`, `strength`, source refs, evidence refs, subject linkage, timestamps, `limitations`, `warnings`, `blockers`, `summary`.

---

## 6. Evidence kind / status / strength semantics

**Kind** (`CapabilityEvidenceKind`): closed-world enum including `EVALUATION_RESULT`, `EVALUATION_RESULT_SET`, and future-ready kinds (`BENCHMARK_RUN`, `REGRESSION_RUN`, etc.). This patch does not claim benchmark/regression runners exist.

**Status** (`CapabilityEvidenceStatus`):

| Status | Meaning |
|--------|---------|
| DRAFT | Incomplete evidence container |
| CANDIDATE | Partial support signal |
| USABLE | Admissible for future claim binding — **not VERIFIED** |
| INSUFFICIENT | Not enough evidence |
| CONFLICTED | Contradictory evidence |
| STALE | Outdated evidence |
| EXPIRED | Past validity window |
| REVOKED | Operator/system revoked |
| INVALID | Structurally or logically invalid |
| REJECTED | Evaluation rejected |

**Strength** (`CapabilityEvidenceStrength`): categorical only — `NONE`, `WEAK`, `ADEQUATE`, `STRONG`, `CONFLICTED`, `UNKNOWN`. No numeric score.

## 7. Mapping from EvaluationResult

`capability_evidence_from_evaluation_result()` rules:

| Evaluation signal | Evidence status |
|-------------------|-----------------|
| SUPPORTED + ADEQUATE/STRONG | USABLE |
| PARTIALLY_SUPPORTED | CANDIDATE |
| INSUFFICIENT_EVIDENCE | INSUFFICIENT |
| CONFLICTED | CONFLICTED |
| REJECTED | REJECTED |
| BLOCKED | INVALID or REJECTED |
| ERROR outcome | INVALID |

| Evidence quality | Strength / status |
|------------------|-------------------|
| STRONG | STRONG |
| ADEQUATE | ADEQUATE |
| WEAK | WEAK |
| NONE | NONE |
| CONFLICTED | CONFLICTED |
| STALE | STALE status, WEAK or UNKNOWN strength |
| UNKNOWN | UNKNOWN |

Never produces `VERIFIED`.

---

## 8. Mapping from EvaluationResultSet

`capability_evidence_from_result_set()` uses aggregate verdict, outcome, and evidence quality from the result set. Same status/strength mapping as single results. Kind is `EVALUATION_RESULT_SET`. Source refs include `source_result_set_ids`.

---

## 9. Evidence validation rules

`validate_capability_evidence_record()` catches:

- Empty `evidence_id`
- USABLE with WEAK / NONE / UNKNOWN / CONFLICTED strength
- USABLE with no source result, source result set, or evidence refs
- CONFLICTED without warning or blocker
- INVALID without blocker
- EXPIRED marked USABLE
- REVOKED marked USABLE

Does not mutate the record.

---

## 10. Evidence aggregation rules

`aggregate_capability_evidence_records()`:

- Empty records → INSUFFICIENT or INVALID with blocker
- INVALID / REVOKED dominates and blocks aggregate USABLE
- CONFLICTED blocks aggregate USABLE
- EXPIRED / STALE degrades aggregate
- INSUFFICIENT dominates only if no usable records
- USABLE only if at least one usable record and no blockers/conflicts
- STRONG only if strong usable evidence exists and no conflict
- ADEQUATE if usable adequate evidence exists and no strong evidence
- No numeric score

---

## 11. Evidence link model

`CapabilityEvidenceLink` connects evidence to subjects/claims with `relationship` (string), `supports_claim_id`, `supports_capability_id`, `required`, `satisfied`, `reason`.

Suggested relationships: `supports_capability_claim`, `supports_evaluation_subject`, `supports_lifecycle_capability`, `supports_autonomy_claim`, `supports_skill_candidate`.

`build_capability_evidence_link()` fails closed on empty `link_id`, `evidence_id`, `subject_id`, `subject_type`, or `relationship`.

## 14. Known limitations

- Evidence records do not verify capability — binding is deferred to P1.5.7
- No verification levels (P1.5.15) or claim decision impact
- No benchmark/regression execution despite future-ready evidence kinds
- CLI is read-only; no fixture validator subcommand in this patch
- Evidence refs are references, not proof of truth
