## 6. PolicyProjectionContract v1 Documentation

**Module:** `src/agentic_runtime/policy_cards/projection_contract.py`

### Contract fields

| Field | Value / role |
|-------|--------------|
| `contract_version` | `policy_projection.v1` |
| `projection_id` | Optional identifier when supplied |
| `projection_hash` | SHA-256 over canonical section dict (prefix `sha256:` in CLI text) |
| `generated_by` | `custos-v0-p1617` |
| `source` | Top-level source label (typically `LIVE`) |
| `sections` | Eight subsystem sections (see below) |
| `readiness` | Nine booleans: registry, resolver, conflict_algebra, resolution_trace, violation_trace, harness, cli_binding, shell_binding, trace_binding |
| `unavailable_reasons` | Contract-level reasons (e.g. `SHELL_BINDING_UNAVAILABLE`) |
| `errors` | Safe error codes/messages when build fails partially |
| `metadata` | JSON-safe, sanitized (no secrets/command bodies) |

### Section IDs

1. `policy_registry`
2. `policy_resolver`
3. `conflict_algebra`
4. `resolution_trace`
5. `violation_trace`
6. `policy_harness`
7. `cli_binding`
8. `shell_binding`

### Event payload seed

- Event version: `policy_projection_event.v1`
- Event types: `POLICY_PROJECTION_BUILT`, `POLICY_SECTION_AVAILABLE`, `POLICY_SECTION_UNAVAILABLE`, `POLICY_PROJECTION_ERROR`
- No global event bus integration in P1.6 — contract seeds only

### Consumption flow

```
policy_cards/ backend (P1.6.0–P1.6.16)
  → build_policy_projection_contract(cli_binding_available=True)
  → PolicyProjectionContract v1
  → policy_projection_to_json_safe_dict()
  → cli_modules/policy_commands.py (P1.6.18)
  → operator-readable text/JSON
```

CLI/TUI **must** consume the projection contract. It must **not** duplicate backend policy logic or invent LIVE state.

## 8. Source Label Model

| Label | Meaning |
|-------|---------|
| `LIVE` | Real backend/projection/runtime data |
| `TRACE_VERIFIED` | Supported by trace/evidence hash |
| `SIMULATED` | Dry-run/simulation state |
| `DEV_FIXTURE` | Development/test fixture (must be visible) |
| `UNAVAILABLE` | Not implemented, disabled, or intentionally unavailable (must include reason) |
| `ERROR` | Attempted but failed (safe error information required) |

### Rules

1. No operator-facing state may be shown without source truth.
2. `LIVE` must never label fake, fixture, simulated, planned, or unavailable state.
3. `TRACE_VERIFIED` requires trace/evidence hash or equivalent evidence reference.
4. `DEV_FIXTURE` must be visible when test/demo fixture data is used.
5. `UNAVAILABLE` must include a reason.
6. `ERROR` must include safe error information.
7. Shell UI remains `UNAVAILABLE` unless actually implemented.
8. Backend remains source of truth.

## 9. Operator Test / Runbook

From repository root with project venv:

```bash
# Projection status (text)
.venv/bin/python -m agentic_runtime.cli policy status

# Projection JSON (validate contract_version + projection_hash)
.venv/bin/python -m agentic_runtime.cli policy projection --json

# Unavailable sections (expect shell_binding)
.venv/bin/python -m agentic_runtime.cli policy unavailable

# Harness inventory
.venv/bin/python -m agentic_runtime.cli policy harness list

# Harness suite (shadow-only; enforced: false)
.venv/bin/python -m agentic_runtime.cli policy harness run

# Single case
.venv/bin/python -m agentic_runtime.cli policy harness run --case deny_beats_allow
```

**Success markers:**

- Text output contains `policy_projection.v1` and `Projection Hash: sha256:` (64 hex chars)
- JSON output contains `"contract_version": "policy_projection.v1"` and non-empty `"projection_hash"`
- `sections.cli_binding.source` is `"LIVE"`; `sections.shell_binding.source` is `"UNAVAILABLE"`
- Harness output always shows `enforced: false` or `"enforced": false`

**Honest UNAVAILABLE:** `policy unavailable` lists `shell_binding` with reason "Shell binding not implemented in P1.6".

## 13. Known Limitations

- Custos v0 resolver is **shadow-only** (`WOULD_*` actions); P0 runtime remains authoritative
- Projection reports **module availability**, not live runtime enforcement state
- Trace sections report `LIVE` for module presence; `TRACE_VERIFIED` requires caller-supplied evidence hashes
- P1.6.14/P1.6.15 trace evidence is trace-compatible but not written to canonical Ledger during projection build
- Harness registry is a fixed built-in matrix (14 scenarios); no external suite loading
- Invalid top-level CLI subcommand uses argparse exit `2`, not handler exit `3`
