## 2. Root Cause of Demo Crash

**Location:** `src/agentic_runtime/demo.py:207` (pre-patch)

```python
banner("RESULT")
sk = kernel.skills.all()[0]   # IndexError when list is empty
```

**Why it crashed:** The maturation loop (Section 6 of the demo) runs the entity 6 times. Each run returns `status=partially_completed` because the `run_tests` step is never approved by the `AutoApprover` (the demo approver only approves `read_file`, `edit_file`, and `run_tests` — but the policy marks `run_shell`/`run_tests` as HIGH-risk, and the card ceiling for the maturation kernel is HIGH, not MEDIUM). Without a successful test run, the skill compilation evidence gate is never satisfied, so `kernel.skills.all()` returns `[]`. The unchecked `[0]` indexing then raises `IndexError`.

**Fix:** Added a guard:

```python
skills = kernel.skills.all()
if not skills:
    print("  No compiled skills — evidence gates were not satisfied.")
    print("  This is a safe governed outcome, not a runtime error.")
    print("  Escalation / human review is the correct governed path when")
    print("  the runtime cannot promote a skill without sufficient evidence.")
    print(f"\n  trace intact: ...")
else:
    sk = skills[0]
    ...
```

No skill is faked. No promotion gate is weakened. The demo is honest.

## 5. Sandbox Timeout / CPU Limit Check Result

**Finding: MISMATCH CONFIRMED AND FIXED.**

`_profile_templates()` in `sandbox_policy.py` defines `restricted_local` with `max_timeout_seconds=30.0`. But `materialize_sandbox_backend` was creating `UnsafeLocalSandbox` without passing `cpu_seconds`, so the rlimit defaulted to 10 seconds.

**Pre-patch:**
```python
return UnsafeLocalSandbox(
    root=root,
    max_output_bytes=profile.max_output_bytes,
)
```

**Post-patch:**
```python
return UnsafeLocalSandbox(
    root=root,
    cpu_seconds=int(profile.max_timeout_seconds),
    max_output_bytes=profile.max_output_bytes,
)
```

This affects all `UnsafeLocalSandbox`-backed profiles: `restricted_local` (30s), `unsafe_local_demo` (60s), and `no_exec_readonly` (10s — no change, matches default). Docker and Bubblewrap backends are unaffected (they don't use `cpu_seconds`).

## 8. Known Limitations

- **No skill promotion in narrative demo**: The maturation loop produces `partially_completed` runs because the demo `AutoApprover` does not satisfy all evidence gates for skill compilation. This is correct governed behavior; the demo now reports it honestly rather than crashing.
- **CLI alpha-seal smoke test uses `--skip-tests`**: Running `alpha-seal --skip-coverage` inside the test suite creates a nested pytest invocation that may timeout. The smoke test uses `--skip-tests` instead, which verifies docs/compile/sandbox readiness. Full `alpha-seal --skip-coverage` is verified manually (confirmed exit 0 above).
- **CLI verify smoke test is not skipped when inside pytest**: `test_cli_verify_exits_zero` runs a subprocess pytest (not recursive — the subprocess doesn't trigger the outer test suite again). It passes but adds ~20s to the test run.
- Default sandbox is `UnsafeLocalSandbox` — not a production security boundary.
