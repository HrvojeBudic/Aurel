## Implemented

Prompt Policy Card Model v1 — a closed-world, deterministic, hash-ready, strict
deny-by-default policy card model defining prompt sources, trust levels, roles,
handling decisions, injection-risk vocabulary and prompt boundary requirements.
Strict defaults preserve instruction hierarchy and ensure the core Aurel law:
**untrusted content may inform, but must never command.** The layer is
model/schema/validation only — it does not compile prompts, assemble context,
enforce instruction hierarchy, detect prompt injection or jailbreaks, or block
tools/memory at runtime.

- 7 enums:
  - `PromptSourceType` (19 values: system/developer/operator/task/agent prompts, tool_output, retrieved_memory, retrieved_document, web/email/file/code/external_api content, evaluation/critic/planner/reflection/generated prompts, unknown)
  - `PromptTrustLevel` (10 values)
  - `PromptRole` (16 values)
  - `PromptPolicyDecision` (10 values)
  - `PromptInjectionRisk` (5 values)
  - `PromptInjectionPattern` (15 values)
  - `PromptBoundaryRequirementType` (14 values)
- 5 frozen dataclasses: `PromptBoundaryRequirement`, `PromptInjectionSignal`, `PromptHandlingRule`, `PromptPolicyCard`, `PromptPolicyValidationIssue`, `PromptPolicyValidationResult`
- Container pattern: `PromptPolicyCard` wraps generic `PolicyCard(kind="prompt")`
- Validation: strict deny-by-default default decision; unknown source cannot be trusted; external content cannot be instruction authority; tool output is data/context only; retrieved memory is context only (no tools/memory/policy/identity overreach); untrusted trust levels cannot request tools, write memory, modify policy, or modify identity; high/critical injection risk cannot pair with allow + instruction authority; closed-world field/enum checks; dangerous metadata rejection
- Deterministic canonical serialization + SHA-256 hashing
- Dict loader and dict validator
- Default factory `create_default_prompt_policy_card()` with 15 strict rules (system_prompt → unknown)

## Validation added

Card-level: supported schema version, generic kind = `prompt`, strict deny-by-default,
non-empty prompt rules, per-rule enum validity (source/trust/role/decision/injection risk,
nested signal patterns/risks, requirement types). Rule-level safety: unknown source cannot
be trusted; external source cannot be instruction; untrusted trust cannot be instruction;
tool_output cannot be instruction; retrieved_memory cannot be instruction or overreach into
tools/memory/policy/identity; untrusted cannot request tools / write memory / modify policy /
modify identity; high/critical effective injection risk (rule or signals) cannot pair with
allow + instruction authority.

## Known limitations

- Validation is structural/semantic only; no runtime prompt compilation, instruction-hierarchy enforcement, injection detection, or resolver binding.
- Trust elevation of retrieved/external content is intentionally impossible in P1.6.8; only a future verified/canon resolver may elevate it under strict rules.
- Risk tiers/oversight are referenced as strings (`risk_ceiling`, `required_oversight`) to avoid cross-module coupling, consistent with P1.6.6/P1.6.7.
- Default card is not globally registered (no global config registration pattern exists yet).
- P1.6.8S resolved the previously noted bare-`python3` autonomy/measured-autonomy CLI subprocess issue with shared `tests/cli_helpers.py`.

## Intentional non-scope

No prompt compiler rewrite, prompt assembly engine, runtime instruction-hierarchy
enforcement, prompt injection detector, jailbreak detector, tool-call runtime blocking,
memory write enforcement, identity compiler changes, policy runtime resolver, policy
conflict detector, simulation mode, trace hook, CLI, report generator, or P25/P29 hardening
were implemented.
