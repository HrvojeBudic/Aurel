## 8. P1.6.8 Prompt Policy Card Verification

Verified Prompt Policy Card Model reality:

- implementation file exists: `src/agentic_runtime/policy_cards/prompt_policy.py`
- schema file exists: `src/agentic_runtime/policy_cards/prompt_policy_schema.py`
- error taxonomy exists and is imported/exported
- canonical serialization exists: `prompt_policy_card_to_canonical_dict()` and `serialize_prompt_policy_card_canonical()`
- deterministic hash readiness exists: `compute_prompt_policy_card_hash()`
- closed-world loaders reject unknown and dangerous fields
- unknown fields and dangerous metadata are rejected
- default decision is deny-by-default
- untrusted content may inform but cannot command, request tools, write memory, or modify policy/identity
- tool output is data/context, not command
- retrieved memory is context, not automatic authority
- high/critical injection risk cannot pair with allow + instruction authority
- generic `PolicyCard(kind="prompt")` compatibility is enforced
- tests exist and pass: `tests/test_prompt_policy_cards_p168.py` (74 passed)
- exports are updated through `agentic_runtime.policy_cards`
- docs and report now state P1.6.8 accurately

The P1.6.8 implementation follows the P1.6.3-P1.6.7 family pattern: typed card wraps generic `PolicyCard`, schema module owns constants/defaults, loader is closed-world, validator is semantic and fail-closed, serialization is deterministic, hash is SHA-256 over canonical JSON, and no runtime resolver/enforcement is introduced.
