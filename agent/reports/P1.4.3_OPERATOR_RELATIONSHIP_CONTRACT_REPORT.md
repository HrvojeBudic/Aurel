**Date:** 2026-06-21

## 1. Summary

P1.4.3 implements Aurel's **authority relationship anchor**. The Operator Relationship Contract loads from `config/aurel/operator_contract.yaml` into frozen typed dataclasses, validates all principal/delegate authority, relationship behavior, non-manipulation, execution authority, accountability, and boundary rules plus the ORC-001–ORC-008 invariant registry, computes a deterministic SHA-256 hash, builds an `AuthorityRelation` anchor, produces a prompt-safe summary, and exposes CLI commands.

The contract defines the formal principal/delegate relationship: Operator remains final authority; Aurel is advisor, challenger, and executor under Operator authority. It is not persona, autonomy, policy cards, delegation mesh, approval workbench, or non-repudiation ledger.

Canonical contract hash: `2211c6c0c5702b9a749b1cf172fb3816659c758de545e0fc71248c7f1fd8e5ed`

## 3. Contract schema summary

Top-level: `schema_version`, `name`, `contract_class: principal_delegate_relationship`, `applies_to_agent: Aurel`.

Sections: `parties` (principal/delegate with id/role/type), `authority` (8 booleans), `relationship_behavior` (7 booleans), `non_manipulation` (6 booleans), `execution_authority` (5 booleans), `accountability` (5 booleans), `future_placeholders` (4 null refs), `boundaries` (7 booleans), `invariants` (ORC-001..008), `notes`.

Typed objects: `AurelOperatorContract`, `ContractParty`, `OperatorContractParties`, `OperatorAuthorityRules`, `RelationshipBehaviorRules`, `NonManipulationRules`, `ExecutionAuthorityRules`, `AccountabilityRules`, `OperatorFuturePlaceholders`, `OperatorContractBoundaries`, `OperatorContractInvariant`, `OperatorContractHash`, `OperatorContractValidationResult`, `OperatorContractAttestation`, `OperatorContractSafeSummary`, `AuthorityRelation`.

## 4. Principal/delegate authority relation summary

| Party | ID | Role | Type |
|-------|-----|------|------|
| Principal (Operator) | `operator.primary` | `final_authority` | `human_operator` |
| Delegate (Aurel) | `aurel.local.operator.primary` | `advisor_executor_under_authority` | `ai_agent` |

`build_authority_relation()` sets `final_authority` to the principal id (`operator.primary`). Delegate cannot self-escalate or replace principal. No scopes, grants, or delegation mesh.

## 6. Validation rules implemented

- Identity: `applies_to_agent == Aurel`, `contract_class == principal_delegate_relationship`
- Parties: principal role/type, delegate role/type
- Authority: all 8 required booleans
- Relationship behavior: all 7 required booleans (`disagreement_allowed: false` is hard fail)
- Non-manipulation: all 6 required true
- Execution authority: all 5 required booleans
- Accountability: all 5 required true
- Boundaries: all 7 required true
- Invariants: non-empty id/key/statement/rationale; critical => immutable + fail_boot; unknown key fails; expected_value must match resolved field

---

## 7. Hashing behavior

`contract_to_canonical_dict()` produces sorted primitive dict (invariants sorted by `id`); `json.dumps(sort_keys=True, separators=(",", ":"))`; SHA-256. Verified deterministic, YAML-order-invariant, and sensitive to critical authority changes.

---

## 8. AuthorityRelation behavior

`build_authority_relation(contract)` returns `AuthorityRelation` with principal/delegate ids and roles, `final_authority` = principal id, `delegate_can_self_escalate` and `delegate_can_replace_principal` from authority rules. Relationship anchor only — prepared for P1.4.15 and P1.8.

---

## 9. Safe summary behavior

`build_operator_contract_safe_summary()` returns `OperatorContractSafeSummary` with principal/delegate summaries plus authority, disagreement, challenge, non-manipulation, execution-authority-boundary, and accountability rule tuples. Deterministic. No raw YAML, no tool-permission or autonomy-granting language. Preparation object for P1.4.5 — not the compiler.

## 13. Known limitations

- Contract is not wired into runtime boot or prompt rendering — load/validate/hash/summary only
- Safe summary is a preparation object; actual prompt compilation is P1.4.5
- Attestation file requires explicit `--write`; no silent writes on import
- `AuthorityRelation` is an anchor only; full Principal/Delegate Model is P1.4.15
- Future placeholder refs (`autonomy_session_ref`, etc.) are null — no runtime linkage yet
- No enforcement linkage to policy/approval runtime (intentional — contract is relationship anchor, not policy)
