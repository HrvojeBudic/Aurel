## 1. Summary

P1.5.5 creates the governed evaluation run envelope layer. Core law: **No governed evaluation execution without a valid run envelope.** The envelope binds registered subjects, resolved criteria, evidence requirements, evaluator metadata, and sparse-context trace requirements — it does NOT execute evaluation, create EvaluationResult, verify capability, or call LLMs/tools.

## 5–7. Run envelope model

Run envelope binds: `subject_entry` (from P1.5.3), `criteria_resolution` (from P1.5.4), `evaluator_type`/`evaluator_ref`, `policy_refs`, auto-derived `evidence_requirements`, 5 sparse context bools, and `status`/`blockers`/`warnings`.

Status lifecycle: DRAFT → READY/BLOCKED/INVALID. COMPLETED means envelope lifecycle completed, not EvaluationResult created.

Intent: CAPABILITY_CHECK, CLAIM_SUPPORT_CHECK, SPARSE_CONTEXT_CHECK (+6 more).

Mode: DRY_RUN, STATIC_REVIEW, FIXTURE_BASED, HUMAN_REVIEW, LLM_JUDGE_PLANNED, TOOL_EXECUTION_PLANNED. PLANNED modes do NOT execute.

EvaluatorType: DETERMINISTIC, HUMAN, LLM_JUDGE, TOOL_BASED, HYBRID.

---

## 8. Evidence requirement derivation

`build_evidence_requirements_from_criteria()` auto-derives one `EvaluationRunEvidenceRequirement` per criterion with non-NONE evidence requirement. REQUIRED/BLOCKING criteria produce `required=True`. Evidence refs → satisfied; no refs → unsatisfied with missing_reason.

---

## 9. Run readiness validation

`validate_governed_evaluation_run_envelope()` catches: empty run_id, UNKNOWN intent/mode/evaluator, invalid/subject status, criteria resolution blockers, no criteria, unsatisfied required evidence, SPARSE_CONTEXT_CHECK without sparse requirements, READY with blockers.

---

## 10. Sparse Cognition run metadata

5 boolean fields derived from criteria: `sparse_context_required` (SPARSE_CONTEXT_CHECK intent or any sparse criterion kind), `retrieval_trace_required` (RETRIEVAL_TRACE evidence), `context_trace_required` (CONTEXT_TRACE evidence), `evidence_graph_required` (EVIDENCE_GRAPH evidence), `lost_context_risk_required` (LOST_CONTEXT_RISK criterion kind). These are metadata only — ASCL not implemented.

## 13. Known limitations

- Envelopes do NOT execute evaluation — execution is deferred to P1.5.6+
- Evidence satisfaction is simplified (any refs = satisfied); typed ref matching not implemented
- LLM_JUDGE_PLANNED / TOOL_EXECUTION_PLANNED are metadata only
- Sparse run metadata does not run Sparse Context Compiler
