# P1.4.15 — Identity Governance Command Surface

## 1. Summary

P1.4.15 introduces a coherent command surface over the P1.4 identity, autonomy, claim, doctrine, attestation, authority-delta, and consent modules. It adds `identity status` and `identity verify` as top-level commands and ensures all existing subcommand groups (autonomy, claims, doctrine, attestation, authority-delta, consent) are exposed under one unified namespace.

This is a command surface, **not** an interactive agent terminal. It provides stable, testable, JSON-output-capable CLI endpoints for inspection, validation, and automation.

## 3. Scope

P1.4.15 implements:

- `IdentityCliStatus` (OK/DEGRADED/BLOCKED/UNKNOWN), `IdentityCliEnvelope`, `IdentitySubsystemStatus`, `IdentityStatusReport` data models
- `build_identity_cli_envelope()` — standardized JSON envelope with ok/command/status/errors/warnings/result
- `build_identity_status_report()` — lightweight subsystem status probe (read-only)
- `verify_identity_surface()` — non-destructive validation across P1.4 modules (read-only)
- `identity status` CLI command with `--json` and human-readable output
- `identity verify` CLI command with `--json` and human-readable output
- Human-readable formatters that expose blockers and suggested next commands
- All subcommand groups (autonomy, claims, doctrine, attestation, authority-delta, consent) accessible under one namespace

## 4. Non-goals

Not implemented: interactive terminal agent, Codex-like coding loop, Claude-Code-like workspace, full TUI, shell UI, tool execution, new autonomy/claim/doctrine/attestation/consent semantics, P1.4.16 Identity Test Battery, P2 Operator Shell, P8 Coding Agent Harness.

## 5. Command surface vs interactive CLI

P1.4.15 is a **command surface**: stable `python -m agentic_runtime.cli identity <subcommand>` endpoints with deterministic JSON output and human-readable summaries. It is designed for inspection, validation, automation, CI, and tests — not for interactive multi-turn sessions.

## 7. JSON envelope

Every command supports a standardized JSON envelope:

```json
{
  "ok": true,
  "command": "identity.status",
  "status": "OK",
  "errors": [],
  "warnings": [],
  "result": {"subsystem_count": 6}
}
```

Key rules: `ok` is true only when `status == OK` and errors is empty. `errors` and `warnings` are always present. `result` is always a dict.

## 8. Human-readable output format

When degraded or blocked, blockers and suggested next commands are shown prominently.

## 9. Status command

`identity status` probes 6 subsystems (kernel, claims, doctrine, attestation, authority-delta, consent) via lightweight import checks. Subsystem status is OK if the module is importable; BLOCKED or UNKNOWN otherwise. Overall status is OK only when all subsystems are OK.

## 10. Verify command

`identity verify` extends status with additional validator-function-level checks for kernel, doctrine, attestation, and consent modules. It verifies key classes/functions are importable beyond just the module level.

## 11. Subsystem probes

Six subsystems are probed:

| Subsystem | Module |
|-----------|--------|
| `identity_kernel` | `agentic_runtime.identity.kernel` |
| `capability_claims` | `agentic_runtime.identity.capability_claims` |
| `doctrine_registry` | `agentic_runtime.identity.external_doctrine` |
| `source_attestations` | `agentic_runtime.identity.source_attestation` |
| `authority_delta_detector` | `agentic_runtime.identity.authority_delta` |
| `operator_consent_binding` | `agentic_runtime.identity.operator_consent` |

## 12. Read-only guarantees

`identity status`, `identity verify`, and all `show/list/validate/evaluate/measure/compare` commands are read-only. Only `consent grant/deny/revoke` may mutate (via their underlying modules that already support those semantics). Read-only identity commands contain zero hidden writes.

## 13. CLI module structure

```
src/agentic_runtime/identity/identity_cli_surface.py   (new — P1.4.15 surface)
src/agentic_runtime/cli_modules/identity_commands.py   (extended — status/verify handlers)
src/agentic_runtime/cli.py                             (extended — status/verify parser entries)
```

Existing subcommand groups were already wired into `identity_commands.py` and `cli.py`. P1.4.15 only adds `status` and `verify` as direct `identity` subcommands.

## 18. Known limitations

- Subsystem probing uses import checks only — does not verify configuration file integrity, YAML parsing, or runtime state
- No configuration file path inspection (status/verify don't know where config files live)
- No subsystem version tracking
- No health endpoint (HTTP/TCP) — CLI-only
- No metrics/telemetry export from status/verify
- `identity verify` checks function existence but doesn't call validators with actual config data
