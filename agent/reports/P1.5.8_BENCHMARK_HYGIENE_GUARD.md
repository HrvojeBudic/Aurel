# P1.5.8 - Benchmark Hygiene Guard + Sparse Hygiene Readiness

## 1. Summary

P1.5.8 adds the Benchmark Hygiene Guard. It represents benchmark fixture boundaries, classifies contamination and sparse-context hygiene risks, resolves categorical hygiene decisions, and can downgrade an existing `EvidenceClaimBinding`.

Core law: benchmark-derived evidence cannot strongly support a claim unless benchmark hygiene is acceptable.

P1.5.8 only assesses benchmark/context hygiene and may downgrade evidence impact.

## 5. Fixture boundary model

`BenchmarkFixtureBoundary` captures fixture ID/name, source and dataset refs, gold labels, expected outputs, answer keys, dates/version, known exposure refs, allowed/forbidden context refs, negative controls, adversarial case refs, sparse context refs, limitations, warnings, blockers, and summary.

Validation catches:
- empty fixture IDs or names
- missing source/dataset provenance
- gold labels in allowed context
- expected outputs in allowed context
- answer keys in allowed or known exposure refs
- forbidden context overlap with allowed context

## 6. Hygiene status/risk semantics

Hygiene status is categorical: `CLEAN`, `ACCEPTABLE`, `DEGRADED`, `CONTAMINATED`, `STALE`, `INSUFFICIENT_PROVENANCE`, `BLOCKED`, or `UNKNOWN`.

Risk is categorical: `NONE`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`, or `UNKNOWN`.

No numeric hygiene score is introduced.

## 7. Contamination taxonomy

The taxonomy covers:
- training contamination
- context leakage
- fixture leakage
- answer key exposure
- retrieval leakage
- source overexposure
- operator hint leakage
- overfit fixtures
- stale fixtures
- duplicate cases
- lost-context risk
- contradiction omission
- multi-hop edge missing
- unknown contamination

Answer key exposure is critical contamination and blocks support by default.

## 8. Freshness and representativeness model

Freshness is categorical: `CURRENT`, `RECENT`, `AGING`, `STALE`, `EXPIRED`, or `UNKNOWN`.

Representativeness is categorical: `REPRESENTATIVE`, `PARTIAL`, `NARROW`, `SYNTHETIC_ONLY`, `TOY_ONLY`, or `UNKNOWN`.

Unknown provenance, stale fixtures, narrow fixtures, toy-only fixtures, synthetic-only fixtures, and missing negative controls prevent strong support by default.

## 9. Hygiene assessment rules

`assess_benchmark_hygiene()` combines boundary validation, contamination classification, freshness classification, representativeness, policy warnings, and policy blockers into `BenchmarkHygieneAssessment`.

Suggested outcomes implemented:
- critical contamination -> blocked/contaminated assessment
- high contamination -> contaminated or blocked under default policy
- missing provenance -> insufficient provenance
- stale/expired metadata -> stale
- narrow/synthetic/toy/unknown representativeness -> degraded
- clean provenance and no leakage -> clean or acceptable

## 10. Hygiene decision rules

`resolve_hygiene_decision()` turns an assessment into the maximum claim-support impact hygiene allows:
- critical contamination -> unusable, max `NONE`, recommended `BLOCKS/BLOCKED`
- high contamination -> blocked by default, or capped at `WEAK` if policy allows
- degraded hygiene -> capped at `MODERATE` or `WEAK`
- stale hygiene -> capped at `WEAK`
- insufficient provenance -> capped at `WEAK`
- clean/acceptable hygiene -> can allow `STRONG`

The decision is not verification.

## 11. Binding downgrade rules

`apply_hygiene_to_evidence_binding()` returns a new `EvidenceClaimBinding`.

It preserves:
- `claim_id`
- `evidence_id`
- `source_result_ids`
- `source_result_set_ids`

It may downgrade:
- `SUPPORTS` -> `PARTIALLY_SUPPORTS`
- `SUPPORTS` -> `INSUFFICIENT`
- `SUPPORTS` -> `BLOCKS`
- `STRONG` -> `MODERATE`
- `STRONG/MODERATE/WEAK` -> `NONE`

It never increases support above the original binding.

## 12. Sparse Cognition hygiene readiness

P1.5.8 represents sparse-context hygiene risks as metadata:
- context leakage
- retrieval leakage
- source overexposure
- lost-context risk
- contradiction omission
- multi-hop edge missing

Sparse hygiene can warn, degrade, cap support, or block support. It does not implement Sparse Context Compiler, retrieval, evidence graph assembly, SSA, true subquadratic attention, or long-context model training.

## 15. Known limitations

- Hygiene classification is deterministic metadata classification, not benchmark execution.
- Freshness classification is intentionally conservative and does not parse arbitrary date ages.
- Retrieval leakage and sparse-context risks are represented as refs/warnings/metadata only.
- No fixture JSON loader was added; CLI remains status/examples only.
- No adversarial case generation is included; that is P1.5.9.
