## Architectural invariants

1. **Behavioral contracts do not grant authority** — no `authority_grant`, `bypass_policy`, `disable_contract` fields accepted.
2. **Behavioral contracts do not bypass policy cards** — contracts can reference policy card IDs but cannot override them.
3. **Closed-world validation** — unknown top-level fields fail. Dangerous fields fail before unknown field check.
4. **Deterministic serialization** — sorted keys, compact JSON, sub-objects sorted by type enum, refs sorted.
5. **SHA-256 hash readiness** — canonical hash is stable and deterministic.
6. **No runtime enforcement** — contracts define behavioral expectations, not runtime actions.
7. **Policy card error hierarchy extended** — behavioral contract errors inherit from `PolicyCardError`.
8. **Schema versioning required** — `schema_version` is mandatory, only `"1.0"` supported.
9. **Metadata safety** — ~27 dangerous metadata keys rejected.
