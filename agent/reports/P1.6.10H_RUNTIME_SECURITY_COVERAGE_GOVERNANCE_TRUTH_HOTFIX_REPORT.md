**Date:** 2026-06-23

## 1. Purpose

Seal truth alignment after P1.6.10 before moving to P1.6.11 registry binding.
Core objective: **git truth = docs truth = runtime truth = coverage truth = security truth**

## 2. Why This Hotfix Exists

A deep Composer review found credibility risks:

1. **Runtime security default is weaker than the governance language implies.**
   The `restricted_local` profile uses `UnsafeLocalSandbox` as its backend, yet the
   profile name suggests a security boundary. The `materialize_sandbox_backend` function
   directly instantiated `UnsafeLocalSandbox` without the `allow_unsafe=True` gate that
   `create_sandbox()` enforces.

2. **Two sandbox systems are not clearly disambiguated.** P0 runtime sandbox policy
   (`sandbox_policy.py`) and P1.6.9 sandbox policy card (`policy_cards/sandbox.py`)
   share the "sandbox" namespace but serve different roles — one enforces, one models.

3. **P1.6.10 resolver is shadow-only** and must not be mistaken for runtime enforcement.
   Documentation must clearly state what WOULD happen vs what DOES happen.

4. **Snapshot path traversal vulnerability.** `read_snapshot_file` used raw `os.path.join`
   without the `CanonicalPathResolver` that protects all other filesystem operations.

5. **Coverage measurement was unreliable.** The `pyproject.toml` coverage config used
   `agentic_runtime` as the source, which may not match the `src/` layout.

6. **Local Composer state pollutes git status.** `.composer/` and `.strategic-composer/`
   directories appeared in `git status --short`.

## 7. Snapshot Path Traversal Fix

**File:** `src/agentic_runtime/sandbox.py`
**Class:** `_WorkspaceBackend`
**Method:** `read_snapshot_file(snapshot_id, rel)`

### Before (vulnerable):

```python
def read_snapshot_file(self, snapshot_id: str, rel: str) -> str:
    src = self._snapshots.get(snapshot_id)
    if not src:
        raise KeyError(f"unknown snapshot {snapshot_id}")
    path = os.path.join(src, rel)
    with open(path, "r", encoding="utf-8", errors="replace") as f:
        return f.read()
```

### After (fixed):

```python
def read_snapshot_file(self, snapshot_id: str, rel: str) -> str:
    src = self._snapshots.get(snapshot_id)
    if not src:
        raise KeyError(f"unknown snapshot {snapshot_id}")
    try:
        resolved = CanonicalPathResolver(src).resolve(rel)
        path = resolved.absolute
    except PathResolutionError as e:
        raise PermissionError(
            f"snapshot path rejected: {e}"
        ) from e
    with open(path, "r", encoding="utf-8", errors="replace") as f:
        return f.read()
```

### What's rejected:
- Parent traversal (`../`)
- Nested traversal (`nested/../../outside.txt`)
- Absolute paths (`/etc/passwd`)
- Symlink escapes (resolved via `os.path.realpath`)
- Empty paths

### What still works:
- Normal relative paths (`logs/result.txt`)
- Nested paths within snapshot (`nested/file.txt`)
- Verifier integration (`verify_edit`, `verify_patch`)

### Design:
The fix uses `CanonicalPathResolver` — the same resolver already used by
`read_file`, `write_file`, and `delete_file` on the workspace root. A fresh
resolver is instantiated per snapshot directory for clean root confinement.
Error messages intentionally do not expose host paths.

## 8. Unsafe / RestrictedLocal Sandbox Honesty

**File:** `src/agentic_runtime/sandbox_policy.py`
**Function:** `materialize_sandbox_backend`

### Before (implicit unsafe):

```python
return UnsafeLocalSandbox(
    root=root,
    cpu_seconds=int(profile.max_timeout_seconds),
    max_output_bytes=profile.max_output_bytes,
)
```

### After (explicit allow_unsafe):

```python
return create_sandbox(
    SandboxMode.UNSAFE_LOCAL,
    root=root,
    allow_unsafe=True,
    cpu_seconds=int(profile.max_timeout_seconds),
    max_output_bytes=profile.max_output_bytes,
)
```

### What changed:
- `materialize_sandbox_backend` now routes non-hard backends through `create_sandbox`
  with the explicit `allow_unsafe=True` gate.
- `restricted_local` and `no_exec_readonly` profiles still use `UnsafeLocalSandbox`
  (no behavior change) — but the safety trade-off is now explicit at the factory level.
- `SandboxDiagnostics` already reported `unsafe=True`, `hard_isolated=False`, and
  the warning "not a hard sandbox boundary" for restricted_local — no diagnostic change needed.

### Import addition:
`create_sandbox` added to `from .sandbox import (...)` in `sandbox_policy.py`.

## 13. Remaining Debt

1. **`_WorkspaceBackend.snapshot()` method** (lines 271-287 in `sandbox.py`) also
   uses raw `os.path.join` and `shutil.copytree` without path validation. The
   snapshot ID is generated internally (not user-supplied), so the attack surface
   is minimal, but a future hardening pass should apply `CanonicalPathResolver`
   consistently.

2. **`restricted_local` profile still uses `UnsafeLocalSandbox`.** This is a
   truth-only fix. The profile declares "policy-restricted but uses
   UnsafeLocalSandbox; not a hard sandbox boundary" in diagnostics. When Docker
   or Bubblewrap becomes available, restricted_local should be migrated to a
   hard-isolated backend — or explicitly documented as "local-only, policy-restricted,
   no real isolation, suitable for trusted environments."

3. **Coverage configuration in `pyproject.toml`** uses `source = ["agentic_runtime"]`
   rather than `source = ["src/agentic_runtime"]`. This works when `PYTHONPATH=src`
   is set (which the config does via `pythonpath = ["src", "."]`), but the canonical
   CLI command `--cov=src/agentic_runtime` is more explicit. Consider updating
   `pyproject.toml` in P1.6.11.

4. **`ProfiledSandbox.read_snapshot_file` delegates to `self._backend.read_snapshot_file`**
   — now fully protected via the backend fix. No separate fix needed in the wrapper.
