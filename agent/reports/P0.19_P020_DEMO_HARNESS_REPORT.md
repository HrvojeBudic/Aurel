## Demo harness architecture

```
DemoScenario (buggy_calculator)
    ↓
DemoRepoFactory.create() → temp repo (no git)
    ↓
run_tests() → verify initial failure
    ↓
RepositoryAgentLoop.run(RepoTaskRequest)
    plan → patch → test → repair (bounded)
    ↓
run_tests() → independent final verification
    ↓
DemoRunReport (honest status + summaries)
```

**Contracts:**

- `DemoScenario` — scenario metadata, files, constraints, sandbox profile
- `DemoRepoFactory` — materialize repo under `tmp_path` / parent directory
- `DemoHarnessRequest` — scenario id, apply/dry-run, optional kernel injection
- `DemoHarnessResult` / `DemoRunReport` — structured outcome

## Demo scenario: buggy_calculator

| Field | Value |
|-------|-------|
| `scenario_id` | `buggy_calculator` |
| Bug | `add(a, b)` returns `a - b` |
| Test | `assert add(2, 3) == 5` |
| Objective | `replace 'return a - b' with 'return a + b' in calculator.py` |
| Allowed paths | `calculator.py`, `test_calculator.py`, `pyproject.toml` |
| Max files changed | 1 |
| Sandbox | `restricted_local` (apply) |
| Test command | `{sys.executable} -m pytest -q` |

## How to run harness

```bash
# Plan-only (default)
PYTHONPATH=src python -m agentic_runtime.cli demo-harness buggy_calculator

# Apply patch through RepositoryAgentLoop
PYTHONPATH=src python -m agentic_runtime.cli demo-harness buggy_calculator --apply

# List scenarios
PYTHONPATH=src python -m agentic_runtime.cli demo-harness list

# Dry-run with approval preview
PYTHONPATH=src python -m agentic_runtime.cli demo-harness buggy_calculator --dry-run
```

Programmatic:

```python
from agentic_runtime.demo_harness import DemoHarness, DemoHarnessRequest

report = DemoHarness().run(DemoHarnessRequest(
    scenario_id="buggy_calculator",
    repo_parent="/tmp",
    apply=True,
))
print(report.final_status, report.files_changed)
```

## Initial failure verification

Before invoking the repository agent, the harness runs tests via subprocess. For `buggy_calculator`, initial tests **must fail**. If they pass unexpectedly, the harness returns `final_status="harness_failed"` — no fake success.

## Final success/failure verification

After `RepositoryAgentLoop` completes (when `apply=True`):

1. Agent `CodeTaskReport.test_result` is recorded
2. Independent `run_tests()` verifies outcome
3. Test files are checked for silent weakening
4. Changed files must stay within `allowed_paths` and `max_files_changed`

Status is `failed` if either agent or independent final tests fail.

## Approval integration

- `DemoRunReport.approval_summary` populated from `CodeTaskReport.approval_summaries`
- Plan-only and dry-run modes record approval requirements before apply
- Default `approval_mode="auto"` with repo R0–R3 envelope (P0.17.1)

## Sandbox integration

- Apply runs use scenario `sandbox_profile` (`restricted_local` by default)
- `sandbox_profile` and `sandbox_violations` recorded on report
- Tests inject `UnsafeLocalSandbox` via `kernel_factory` for deterministic CI

## Praxis integration

- `RepositoryAgentLoop` finalizes praxis via `_finalize_report`
- `DemoRunReport.praxis_summary` includes candidate counts and limitations
- `plan_verification.praxis_recorded` checked on apply runs

## Known limitations

- Planning remains deterministic (`CodeTaskPlanner` replace-in-objective pattern); P0.20 may swap in a real model planner
- `buggy_calculator` is a single-file arithmetic fix — not representative of large-repo work
- Initial pytest run can create bytecode cache; harness clears `__pycache__` before agent loop to avoid stale imports
- CLI default is plan-only; `--apply` required for full loop
- No git initialization in demo repos (by design)
- Docker/bubblewrap profiles not used in default harness path
