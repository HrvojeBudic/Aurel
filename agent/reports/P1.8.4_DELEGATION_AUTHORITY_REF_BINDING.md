# P1.8.4 — Delegation AuthorityRef Binding

**Task ID:** P1.8.4
**Date:** 2026-06-27
**Roadmap:** Aurel Roadmap v5.1 — Integration-First
**Parent section:** P1.8 — Delegation / Non-Repudiation / Agent Identity Mesh
**Status:** COMPLETE

## Purpose

Create a deterministic, versioned, JSON-safe, side-effect-free authority-reference binding layer for delegation authority context. The layer binds reference-only authority context to DelegationRef / DelegationIdentity / DelegationRoleBindingSet / DelegationConstraintSet without granting authority, verifying authority, creating approval, calling policy/Custos, enforcing constraints, executing runtime actions, writing trace, or writing Ledger.

## Scope

### Implemented

- `DelegationAuthorityRefKind` enum: OPERATOR_DECLARED, POLICY_CONTEXT_REFERENCED, PATH_AUTHORITY_REFERENCED, SYSTEM_DECLARED, CONSTRAINT_CONTEXT_REFERENCED, UNKNOWN
- `DelegationAuthorityRefStatus` enum: REFERENCE_ONLY, DECLARED, UNAVAILABLE, ERROR, UNKNOWN
- `DelegationAuthorityRef` frozen dataclass: enriched authority context reference with `schema_version`, `delegation_ref_id`, `constraint_context_ref`, `authority_status`, `authority_ref_hash`
- `DelegationAuthorityBinding` frozen dataclass: binding between authority ref and delegation identity/role/constraint context with `binding_hash`
- `DelegationAuthorityBindingSet` frozen dataclass: collection of authority refs/bindings with deterministic ordering and `authority_binding_set_hash`
- `DelegationAuthoritySideEffects` frozen dataclass: 11 all-false booleans (hard proof of non-authorizing, non-verifying, non-mutating)
- `DelegationAuthorityStatusReport` frozen dataclass: readiness report with 16 unavailable surface reasons
- Deterministic hash functions: `compute_authority_ref_hash`, `compute_authority_binding_hash`, `compute_authority_binding_set_hash`, `compute_authority_status_report_hash`
- Builder functions: `build_delegation_authority_ref`, `build_delegation_authority_binding`, `build_delegation_authority_binding_set`, `build_delegation_authority_status_report`
- Serialization: `serialize_delegation_authority_ref`, `serialize_delegation_authority_binding_set`
- Hash accessors: `hash_delegation_authority_ref`, `hash_delegation_authority_binding_set`
- Closed-world field validation via `from_dict` / `validate_known_fields`
- Versioned schemas: `delegation_authority_ref.v1`, `delegation_authority_binding.v1`, `delegation_authority_binding_set.v1`, `delegation_authority_side_effects.v1`, `delegation_authority_status_report.v1`
- `src/agentic_runtime/delegation/__init__.py` exports all P1.8.4 symbols; existing P1.8.0/P1.8.1/P1.8.2/P1.8.3 exports preserved
- Reuses P1.8.0 foundation infrastructure: `stable_hash`, `DelegationSourceLabel`, `validate_known_fields`, parser helpers
- 41 focused tests in `tests/delegation/test_p1_8_4_authority.py`

### Naming note

P1.8.4 `DelegationAuthorityRef` is a richer superset of the foundation (P1.8.0) `DelegationAuthorityRef`. The P1.8.4 version adds `schema_version`, `delegation_ref_id`, `constraint_context_ref`, and `authority_status`. In `__init__.py`, the P1.8.4 import shadows the foundation version (last import wins). The foundation version remains importable from `.foundation`.

## Explicit non-equivalences (core boundary)

- AuthorityRef exists ≠ authority granted
- Authority basis exists ≠ authority verified
- Policy context ref exists ≠ policy/Custos decision
- Path authority ref exists ≠ path authorized
- Operator declaration exists ≠ legal or operational authority proven
- Authority binding exists ≠ approval created
- Authority binding exists ≠ permission granted
- Authority hash exists ≠ TRACE_VERIFIED
- Authority model exists ≠ authority resolver exists
- Authority binding set exists ≠ runtime execution
- Constraint context ref exists ≠ constraint enforced

## Remaining risks / limitations

1. Authority refs describe referenced authority context but do not grant, verify, or enforce authority — enforcement layer is future (P1.8.5+).
2. Authority hashes are deterministic but not TRACE_VERIFIED — trace/Ledger binding is future.
3. No authority resolver, verifier, or grant mechanism exists yet.
4. P1.8.4 `DelegationAuthorityRef` shadows P1.8.0 `DelegationAuthorityRef` in package namespace; downstream consumers should import the foundation version explicitly from `.foundation` if the simpler contract is needed.
5. The P1.8.4 module does not import from or modify runtime, trace, Ledger, policy_cards, path_governance, sandbox, or evaluation layers.
