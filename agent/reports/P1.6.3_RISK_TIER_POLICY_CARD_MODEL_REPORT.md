# P1.6.3 - Risk Tier Policy Card Model Report

## Implemented

- Added `RiskTierPolicyCard` as the first typed policy card model.
- Added R0-R6 `RiskTier` taxonomy.
- Added `ReversibilityLevel`, `OversightLevel`, and `EvidenceExpectation`.
- Added `RiskTierDefinition`, `RiskActionClass`, and `RiskActionClassMapping`.
- Added Risk Tier Policy Card Schema v1 with required/optional/forbidden/canonical fields.
- Added default R0-R6 risk tier definitions.
- Added default seed action-class mappings.
- Added closed-world dict loading and validation.
- Added strict R5 safety validation:
  - requires trace
  - requires evidence
  - requires approval
  - requires explicit Operator confirmation
  - requires irreversible reversibility
  - requires explicit Operator confirmation oversight
- Added strict R6 denied/non-permissive validation:
  - denied oversight
  - denied reversibility
  - no execution
  - no external egress
  - no memory write
  - no tool write
- Added dangerous metadata rejection.
- Added deterministic canonical serialization and SHA-256 canonical hashing.
- Added safe default factory: `create_default_risk_tier_policy_card()`.
- Exported P1.6.3 public API from `agentic_runtime.policy_cards`.

## Intentional non-scope

- no policy runtime resolver
- no automatic risk classifier
- no runtime risk inference
- no runtime enforcement
- no human oversight cards
- no conflict detector
- no simulation mode
- no trace hook
- no CLI
- no report generator
- no P25 hardening

## Known limitations

- Risk tier cards define semantics only. They do not decide applicability, classify actions, grant authority, or enforce runtime behavior.
- Action-class mappings are seed vocabulary for future resolver/classifier work.
- Full-repo ruff/mypy are not clean due existing unrelated issues outside the P1.6.3 surface; focused P1.6 policy card checks pass.
- `python -m agentic_runtime status` is not currently a valid package entry point; `python -m agentic_runtime.cli status` is the working CLI status command.
