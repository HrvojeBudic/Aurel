# P1.4.17 — Agent Lifecycle Eligibility State Machine

## 1. Summary

P1.4.17 implements a governed lifecycle eligibility state machine for agent identities. Every agent identity has a lifecycle state that determines which operational lanes it is eligible to enter. Lifecycle state does NOT grant authority — specific action permissions are still decided by authority scope, autonomy engine, consent binding, tool permissions, and policy cards.

- No runtime permission enforcement
- No tool execution or delegation
- No automatic state mutation
- No identity mesh (P1.8)
- No Custos or policy engine integration
- No specialist lifecycle

## 5. Lifecycle eligibility vs permission engine

Core distinction:
- Lifecycle state = operational lane eligibility (which lanes an identity may enter)
- Specific action permission = still decided by authority scope, autonomy, consent, tool permissions

ACTIVE ≠ "can do everything". ACTIVE = "eligible for governed runtime if all other gates pass".
CANDIDATE ≠ "cannot do anything". CANDIDATE = "eligible for sandbox/evaluation lanes".

## 6. Identity lifecycle vs runtime execution status

Separate concepts:
- Lifecycle state (long-term): DRAFT, CANDIDATE, ACTIVE, RESTRICTED, SUSPENDED, etc.
- Runtime status (short-term): IDLE, RUNNING, BLOCKED, WAITING_FOR_APPROVAL, etc.

P1.4.17 only handles lifecycle eligibility.

## 7. Lifecycle state model

| State | Eligible lanes | Blocked lanes | Required gates |
|-------|---------------|---------------|----------------|
| DRAFT | SANDBOX, LOCAL_READ_ONLY | GOVERNED_RUNTIME, EXTERNAL_EFFECT, DELEGATION, PRODUCTION | identity_validation, source_attestation |
| CANDIDATE | SANDBOX, EVALUATION, LOCAL_READ_ONLY, LOCAL_REVERSIBLE | EXTERNAL_EFFECT, DELEGATION, PRODUCTION | identity_test_battery, source_attestation, claim_boundary |
| ACTIVE | All lanes (by lifecycle alone) | None (by lifecycle alone) | authority_scope, autonomy_decision, consent_if_required, tool_permission, policy_check, claim_boundary |
| RESTRICTED | Reason-sensitive | Reason-dependent | Reason-dependent |
| SUSPENDED | AUDIT_ONLY | GOVERNED_RUNTIME, EXTERNAL_EFFECT, DELEGATION, PRODUCTION | repair_evidence, operator_review |
| DEPRECATED | LOCAL_READ_ONLY, AUDIT_ONLY | GOVERNED_RUNTIME for new work, EXTERNAL_EFFECT, DELEGATION, PRODUCTION | migration_if_needed |
| RETIRED | AUDIT_ONLY | All operational lanes | (none) |
| REVOKED | AUDIT_ONLY | All operational lanes | (none, terminal) |

## 8. Lifecycle reason code taxonomy

24 reason codes across categories:
- Creation/evaluation: INITIAL_CREATION, READY_FOR_EVALUATION, EVALUATION_PASSED, EVALUATION_FAILED
- Authority delta: AUTHORITY_DELTA_UNRESOLVED, AUTHORITY_DELTA_RESOLVED
- Consent: CONSENT_MISSING, CONSENT_GRANTED, CONSENT_REVOKED, CONSENT_EXPIRED
- Attestation: SOURCE_ATTESTATION_VALID, SOURCE_ATTESTATION_FAILED
- Claims: CLAIM_BOUNDARY_VALID, CLAIM_BOUNDARY_VIOLATION
- Doctrine: DOCTRINE_BOUNDARY_VALID, DOCTRINE_BOUNDARY_VIOLATION
- Incidents: POLICY_VIOLATION, SECURITY_INCIDENT, OPERATOR_ACTION
- Deprecation: DEPRECATED_BY_NEW_VERSION, RETIRED_BY_OPERATOR, REVOKED_BY_OPERATOR

## 9. Lifecycle lane model

Lanes are eligibility categories, not permission grants:
- SANDBOX, EVALUATION, LOCAL_READ_ONLY, LOCAL_REVERSIBLE — safe lanes
- GOVERNED_RUNTIME — governed execution
- EXTERNAL_EFFECT, DELEGATION, PRODUCTION — high-risk lanes
- AUDIT_ONLY — read-only audit access

## 10. Transition request / decision / event model

Request: agent_id + old_state + requested_state + reason_code + reason_text + evidence/consent/battery refs
Decision: allowed + resulting_state + requires_evidence/consent/test_battery/operator_review + blockers + warnings
Event: only created if decision.allowed is true; records the transition

## 11. Default transition policy

Allowed transitions:
- DRAFT → CANDIDATE, RETIRED, REVOKED
- CANDIDATE → DRAFT, ACTIVE, RESTRICTED, RETIRED, REVOKED
- ACTIVE → RESTRICTED, SUSPENDED, DEPRECATED, RETIRED, REVOKED
- RESTRICTED → ACTIVE, SUSPENDED, DEPRECATED, RETIRED, REVOKED
- SUSPENDED → RESTRICTED, RETIRED, REVOKED
- DEPRECATED → RETIRED, REVOKED
- RETIRED → REVOKED
- REVOKED → (none, terminal)

Forbidden: DRAFT→ACTIVE, SUSPENDED→ACTIVE, DEPRECATED→ACTIVE, RETIRED→ACTIVE, REVOKED→anything, ACTIVE→DRAFT, RETIRED→CANDIDATE

## 12. Eligibility profile model

Each profile exposes:
- eligible_lanes — lanes the identity may enter
- blocked_lanes — lanes blocked by lifecycle
- required_gates — additional gates beyond lifecycle
- hard_blocked — whether all operational lanes are blocked
- audit_only — whether only audit access remains
- blockers/warnings — specific governance issues

RESTRICTED state is reason-sensitive:
- CONSENT_EXPIRED/CONSENT_REVOKED → blocks EXTERNAL_EFFECT, DELEGATION, PRODUCTION; requires consent_repair
- SECURITY_INCIDENT/SOURCE_ATTESTATION_FAILED → AUDIT_ONLY, hard_blocked; requires incident_review

## 13. Evidence and consent requirements

- Any transition to ACTIVE requires evidence_refs and test_battery_refs
- CANDIDATE→ACTIVE requires EVALUATION_PASSED or OPERATOR_ACTION reason code
- RESTRICTED→ACTIVE requires repair evidence + consent refs if consent-related
- ACTIVE→REVOKED requires REVOKED_BY_OPERATOR, SECURITY_INCIDENT, or OPERATOR_ACTION reason code

## 14. Agent Identity Card integration

Lifecycle state is designed to integrate with AgentIdentityCard:
- Missing lifecycle state defaults to DRAFT
- ACTIVE requires evidence/test battery refs
- REVOKED cannot be runtime eligible
- Lifecycle fields: lifecycle_state, lifecycle_reason, lifecycle_evidence_refs, last_lifecycle_event_ref

## 15. CLI usage

```bash
# Show lifecycle state
python -m agentic_runtime.cli identity lifecycle show --agent-id aurel.core --state CANDIDATE --json

# Build eligibility profile
python -m agentic_runtime.cli identity lifecycle profile --agent-id aurel.core --state RESTRICTED --reason CONSENT_EXPIRED --json

# Validate transition
python -m agentic_runtime.cli identity lifecycle validate-transition \
  --agent-id aurel.core --old-state CANDIDATE --new-state ACTIVE \
  --reason-code EVALUATION_PASSED --reason "battery passed" \
  --evidence-ref report.md --test-battery-ref report.md --json

# Show transition policy
python -m agentic_runtime.cli identity lifecycle transitions --json

# Recommend lifecycle change
python -m agentic_runtime.cli identity lifecycle recommend \
  --agent-id aurel.core --current-state ACTIVE \
  --battery-status FAILED --highest-failed-severity CRITICAL --json
```

## 19. Known limitations

- No runtime enforcement — lifecycle decisions are advisory
- No persistent event log — events are created but not stored
- Recommendation engine covers common patterns but not all edge cases
- No Agent Identity Card schema migration (integration point for existing cards)
- Human formatters are basic text only
