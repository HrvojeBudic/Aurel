# P1.5.6 — Result Classification Engine + Sparse Classification Readiness

## 1. Summary

P1.5.6 created the Result Classification Engine, which translates supplied evaluation observations into standardized evaluation result semantics (EvaluationOutcome, EvaluationVerdict, EvaluationEvidenceQuality, EvaluationConfidenceClass, EvaluationFailureMode, EvaluationCriterionResult, EvaluationResult). Classification is explicitly **not verification** — this patch does not execute evaluation, call LLMs/tools, verify capability, or bind evidence to claims.

## 5. Observation model

18 observation types (10 standard + 7 sparse + UNKNOWN). 7 statuses: PRESENT, MISSING, PARTIAL, CONFLICTED, BLOCKED, INVALID, UNKNOWN.

## 6. Criterion classification model

CriterionClassificationInput → classify_criterion_observation() → CriterionClassificationDecision.

Key rules:
- MISSING + required → INCONCLUSIVE / INSUFFICIENT_EVIDENCE
- MISSING + blocking → FAILED / REJECTED + REQUIRED_CRITERION_FAILED
- CONFLICTED → INCONCLUSIVE / CONFLICTED
- BLOCKED → BLOCKED / BLOCKED
- INVALID → ERROR / UNSUPPORTED
- UNKNOWN → INCONCLUSIVE / INSUFFICIENT_EVIDENCE (never PASSED)
- PRESENT with evidence refs → PASSED / SUPPORTED
- PRESENT without evidence refs → PARTIAL / PARTIALLY_SUPPORTED

## 7. Result classification model

classify_result_from_criterion_decisions() aggregates multiple CriterionClassificationDecisions.

Dominance order: BLOCKED > CONFLICTED > REJECTED > INSUFFICIENT_EVIDENCE > SUPPORTED > MIXED.

## 8. Classification policy

Default policy:
- require_evidence_for_supported = True
- block_on_conflicted_evidence = True
- block_on_missing_required_evidence = True
- allow_unknown_observation_to_pass = False

## 9. Conversion to EvaluationCriterionResult

criterion_decision_to_result() produces P1.5.1 EvaluationCriterionResult objects directly.

## 10. Conversion to EvaluationResult

result_classification_to_evaluation_result() produces P1.5.1 EvaluationResult objects. Does NOT create capability evidence records.

## 11. Sparse Cognition classification readiness

7 sparse observation types classify correctly. Sparse observations are **supplied inputs** — no Sparse Context Compiler, retrieval router, or evidence graph builder is implemented. The classification engine correctly maps:
- PRESENT sparse context → SUPPORTED
- MISSING lost context risk → INSUFFICIENT_EVIDENCE
- CONFLICTED contradiction survival → CONFLICTED

P1.5.6 does NOT claim SSA/subquadratic model attention is implemented.

## 14. Known limitations

- Observation-to-criterion matching is conservative (simple string matching on criterion_id in refs; falls back to order-based pairing)
- No confidence calibration (uses categorical ConfidenceClass, not numeric scores)
- No evaluation execution — classification only interprets supplied observations
- Sparse observations are supplied externally — no ASCL engine produces them
- classify_result_from_observations() does not validate the run envelope (assumes P1.5.5 validation already done)
