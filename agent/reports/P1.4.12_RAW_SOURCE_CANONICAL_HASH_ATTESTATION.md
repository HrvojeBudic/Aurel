# P1.4.12 - Raw Source + Canonical Hash Attestation

## 1. Summary

P1.4.12 adds hash-based source attestation for Aurel identity and doctrine sources. The layer binds the raw source that entered, the canonical typed object Aurel interpreted, the validation result, rejected unknown governance fields, validator metadata, warnings/errors, and evidence references into a JSON-serializable attestation envelope.

P1.4.12 provides hash-based source attestation. It does not provide cryptographic signatures, tamper-proof storage, trust scoring, or capability verification.

## 4. Non-Goals

P1.4.12 does not implement a ledger, Evaluation Mirror, Path Governance, Output Passport, crypto signing, trust scoring, capability promotion, tool execution, or roadmap renumbering.

Hash proves integrity of a seen source. Hash does not prove truth, trust, safety, capability, cryptographic signature, or tamper-proof storage.

Unknown source kinds fail attestation building and validation tests.

## 8. Validation Status Model

`SourceValidationStatus` is closed-world:

- `VALID`
- `INVALID`
- `VALID_WITH_WARNINGS`
- `REJECTED_UNKNOWN_FIELDS`
- `MISSING_SOURCE`
- `SCHEMA_MISMATCH`

`INVALID` requires errors. `REJECTED_UNKNOWN_FIELDS` requires rejected field names. `MISSING_SOURCE` requires errors.

## 9. Raw Hash Vs Canonical Hash

`raw_source_hash` is computed from raw unnormalized bytes/text. For strings, UTF-8 bytes are hashed. Line endings and extra fields are not normalized away.

`canonical_typed_hash` is computed from deterministic JSON over the typed object Aurel understood. Dataclasses, enums, paths, mappings, tuples, lists, and sets are canonicalized with sorted keys and stable separators. Volatile runtime fields such as `created_at` are excluded.

The two hashes are separate concepts and are stored separately in `SourceHashPair` and `SourceAttestation`.

## 10. Attestation Envelope

`SourceAttestation` includes:

- `attestation_id`
- `schema_version = source_attestation.v1`
- `source_kind`, `source_path`, `source_name`
- `raw_source_hash`, `canonical_typed_hash`, `hash_algorithm`
- `validation_status`
- `validator_name`, `validator_version`
- `rejected_unknown_fields`
- `warnings`, `errors`
- `created_at`
- `evidence_refs`

Attestation IDs are deterministic from source kind plus raw/canonical hashes. Timestamps are not included in canonical typed object hashes.

## 16. Known Limitations

- Attestations are hash-based only; no signing keys, secure key storage, rotation, or signature verification are implemented.
- Attestations are not tamper-proof storage and are not trust scores.
- Unknown field rejection focuses on governance, authority, safety, and capability-shaped unknown fields around current identity YAML sources. It does not replace each domain validator.
- Doctrine source attestations currently bind seeded registry source identity/hash plus canonical doctrine objects. Future file-based doctrine registration should bind the exact external raw file or markdown body.
- Attestation timestamps are runtime metadata and are intentionally excluded from canonical typed hashes.
- P1.4.13 Authority Delta and P1.4.14 Operator Consent were intentionally out of scope for this P1.4.12 patch. Both are now delivered in subsequent patches (see `agent/reports/P1.4.13_AUTHORITY_DELTA_DETECTOR.md` and `agent/reports/P1.4.14_OPERATOR_CONSENT_BINDING.md`).
