# P1.7.6 — Path Authority Scope Model

**Status:** COMPLETE — declarative scope model only

**Phase:** P1.7 — Path Governance & Source Trust

## 1. Purpose

P1.7.6 establishes deterministic, JSON-safe, hash-ready path authority scope declaration objects. It models declared subjects, bases, constraints, scopes, and registries without resolver behavior, permission decisioning, enforcement, filesystem access, CLI, trace hooks, or Ledger integration.

Core law: authority scope means declare, not decide. Constraint is not enforcement. Scope registry is not sandbox.

## 3. Implemented

- `PathAuthoritySubjectKind`: OPERATOR, AGENT, TOOL, WORKFLOW, MODEL, RUNTIME, SYSTEM, UNKNOWN
- `PathAuthorityBasis`: OPERATOR_DECLARATION, POLICY_DECLARATION, TRUSTED_ROOT_REGISTRY, SYSTEM_DEFAULT, TASK_CONTEXT, TEST_FIXTURE, UNKNOWN
- `PathAuthorityConstraintKind`: REQUIRES_OPERATOR_REVIEW, REQUIRES_POLICY_REVIEW, REQUIRES_TRACE, REQUIRES_LOCAL_ONLY, REQUIRES_SANDBOX_LATER, REQUIRES_NO_NETWORK_LATER, RESTRICTS_EXECUTE, RESTRICTS_WRITE, RESTRICTS_MEMORY_USE, RESTRICTS_PROMPT_CONTEXT_USE, UNKNOWN
- `PathAuthoritySubject` with deterministic `subject_id`
- `PathAuthorityConstraint` with deterministic `constraint_id`
- `PathAuthorityScope` with optional `root_id`, optional `PathIdentity`, `PathScopeAction` values, constraints, deterministic `scope_id` and `scope_hash`
- `PathAuthorityScopeRegistry` with order-insensitive deterministic `registry_hash`
- `build_path_authority_scope()`
- `build_path_authority_scope_registry()`
- Deterministic hash helpers: `compute_subject_id`, `compute_constraint_id`, `compute_scope_id`, `compute_scope_hash`, `compute_authority_scope_registry_hash`
- Source-label truth for authority scope state
- Closed-world validation; unknown fields reject with `UNKNOWN_FIELD`
- Focused tests (29) for exports, declaration patterns, hash determinism, non-enforcement, and no filesystem access

## 6. Authority Scope Boundary Summary

- Authority scope model is not an authority decision.
- Authority declaration is not runtime permission.
- Subject kind does not grant authority.
- Basis does not grant permission.
- Constraint does not enforce.
- Scope registry is not sandbox.
- `PathScopeAction` remains declaration vocabulary only.
- No allow/deny/can_* APIs exist.

## 7. Governance Boundary

P1.7.6 creates the Path Authority Scope Model; it does not add path governance resolver behavior, source trust resolver behavior, path permission enforcement, filesystem security, runtime enforcement, Ledger writes, approval activation, CLI/TUI binding, Shell UI, filesystem reads, symlink resolution, realpath resolution, or sandbox behavior changes.
