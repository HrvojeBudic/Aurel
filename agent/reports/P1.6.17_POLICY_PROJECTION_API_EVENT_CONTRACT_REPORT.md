# P1.6.17 — Policy Projection/API/Event Contract Report

**Status:** COMPLETE
**Date:** 2026-06-25
**Phase:** P1.6 — Policy Cards & Behavioral Contracts
**Predecessor:** P1.6.16 — Policy Test Harness
**Successor:** P1.6.18 — Policy CLI/TUI Binding

## Purpose

P1.6.17 introduces the versioned policy projection/API/event contract required by the Integration-First roadmap; it does not implement the final CLI binding, enforce policy decisions, write to the Ledger, activate approvals, block commands, or change runtime sandbox behavior.

## Roadmap v5.1 Integration-First Requirement

This vertical slice delivers:

1. **Backend capability** — `projection_contract.py` reads real `policy_cards` modules (registry, resolver, conflict algebra, resolution trace, violation trace, test harness).
2. **Versioned contract/schema** — `PolicyProjectionContract` at `policy_projection.v1` with deterministic JSON-safe canonical payload.
3. **Projection/API/CLI-readable state** — `build_policy_projection_contract()` returns operator-readable governance state as pure Python + JSON-safe dict.
4. **Shell/CLI/TUI binding** — explicitly `UNAVAILABLE` with honest reasons (CLI deferred to P1.6.18; Shell not in P1.6).
5. **Trace/evidence/report binding** — trace sections upgrade to `TRACE_VERIFIED` when evidence hashes are supplied; otherwise `LIVE` module availability.

## Why P1.6.17 Is Not CLI Binding

The earlier "Policy CLI Surface" concept moved to **P1.6.18 — Policy CLI/TUI Binding**. P1.6.17 defines the read-model contract that P1.6.18 will consume. No CLI commands, TUI screens, or Shell UI were added. `cli.py` and `runtime.py` are untouched.

## Relationship to P1.6.16 Policy Test Harness

P1.6.16 validates shadow governance scenarios via the harness. P1.6.17 exposes honest subsystem availability and readiness for operators and future CLI/TUI surfaces — including harness module detection — without running harness scenarios during projection build.

## Projection Contract Schema

| Type | Role |
|------|------|
| `PolicyProjectionContract` | Top-level contract: version, projection_id, projection_hash, sections, readiness, unavailable_reasons, errors |
| `PolicyProjectionSection` | Per-subsystem section with source label, status, capabilities, hashes |
| `PolicyProjectionReadiness` | Nine booleans: registry through trace_binding; cli/shell false in P1.6.17 |
| `PolicyProjectionSnapshot` | Contract + `generated_at` timestamp |
| `PolicyProjectionEvent` | Event payload seed for future event-stream integration |

**Section IDs:** `policy_registry`, `policy_resolver`, `conflict_algebra`, `resolution_trace`, `violation_trace`, `policy_harness`, `cli_binding`, `shell_binding`

## Source Label Model

| Label | Meaning |
|-------|---------|
| `LIVE` | Real backend/module/capability state |
| `TRACE_VERIFIED` | Confirmed by trace/evidence hash present |
| `SIMULATED` | Explicit dry-run/simulation state |
| `DEV_FIXTURE` | Test/development fixture state |
| `UNAVAILABLE` | Capability/binding not implemented (requires reason) |
| `ERROR` | Projection attempted but failed (requires safe error) |

## API / Read-Model Functions

- `build_policy_projection_contract()` — assembles all sections, readiness, hashes
- `build_policy_projection_snapshot()` — contract + UTC timestamp
- `build_policy_projection_event()` — event payload seed
- `policy_projection_to_json_safe_dict()` — CLI-readable JSON-safe dict
- `policy_projection_hash()` — deterministic SHA-256 over canonical dict

Per-section builders: `build_policy_registry_projection()`, `build_policy_resolver_projection()`, `build_policy_conflict_algebra_projection()`, `build_policy_resolution_trace_projection()`, `build_policy_violation_trace_projection()`, `build_policy_harness_projection()`, `build_policy_cli_binding_projection()`, `build_policy_shell_binding_projection()`.

## Event Contract Seed

Event types: `POLICY_PROJECTION_BUILT`, `POLICY_SECTION_AVAILABLE`, `POLICY_SECTION_UNAVAILABLE`, `POLICY_PROJECTION_ERROR`.

Pure payload objects only — no event bus, no Ledger writes, no runtime hookup.

## Known Limitations

- Projection reports module availability, not live runtime enforcement state
- Trace sections are `LIVE` unless caller supplies evidence hashes for `TRACE_VERIFIED`
- No event bus integration — event objects are contract seeds only
- CLI and Shell bindings deferred to P1.6.18+

## What Was Deliberately Not Implemented

- CLI commands (`cli.py` unchanged)
- TUI / Shell UI
- Policy enforcement or fail-closed apply
- Ledger / AurelTrace integration
- Global event bus
- Runtime control-flow changes
