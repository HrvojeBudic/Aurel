# P0.12 Real LLM Adapter Layer Report

**Date:** 2026-06-17  
**Task:** P0.12 Real LLM Adapter Layer

## Summary

Added an optional provider abstraction layer for structured plan generation.
The mock provider remains deterministic and offline by default. OpenAI,
Anthropic, and Ollama adapters are available without adding runtime
dependencies. Providers never execute tools; all model output remains subject to
structured schema validation and the existing `PlanValidator` before the runtime
can create `CommandEnvelope` proposals.

## Provider architecture

Providers implement:

```python
generate_structured_plan(request: ModelRequest) -> ModelResponse
healthcheck() -> ProviderHealth
```

`ModelRouter` adapts providers into the existing `ModelClient` seam. The entity
still calls `router.complete(...)` and then passes returned text to
`PlanValidator`. Provider errors are converted into structured refusal JSON so
planning halts cleanly instead of throwing uncaught exceptions.

## How to select providers

Default:

```bash
AUREL_MODEL_PROVIDER=mock
```

Supported values:

- `mock`
- `openai`
- `anthropic`
- `ollama`

Example:

```bash
AUREL_MODEL_PROVIDER=ollama AUREL_OLLAMA_MODEL=llama3.1 \
  python -m agentic_runtime.cli demo
```

## Known limitations

- Real provider calls are not exercised without API keys/local services.
- No vendor tool-calling is implemented or allowed.
- JSON schema validation is implemented with a lightweight stdlib validator, not
  a full JSON Schema engine.
- Default runtime sandbox is still `UnsafeLocalSandbox`.
