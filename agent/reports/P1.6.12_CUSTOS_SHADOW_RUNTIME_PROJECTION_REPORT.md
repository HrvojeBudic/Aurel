# P1.6.12 Custos Shadow Runtime Projection & Submit Observability Hook Report

## Status

P1.6.12 is implemented as an observability-only bridge. `AgenticRuntime.submit()` remains governed by the existing P0 policy, approval, sandbox, budget, verifier, rollback, trace, and memory pipeline. When explicitly enabled with an explicit `PolicyCardRegistry`, the runtime attaches deterministic Custos shadow projection metadata to `ObservationEnvelope.artifacts["policy_shadow_projection"]` before transition append.

## Observability Boundary

P1.6.12 does not enforce Custos decisions.

- Flag false means no projection work.
- No registry means no projection work, even if the flag is true.
- Runtime creates no default cards.
- Runtime performs no policy-card file discovery.
- Runtime uses no global policy-card state.
- Custos `WOULD_DENY`, `WOULD_REQUIRE_APPROVAL`, and `WOULD_WARN` do not alter `CommandResult`.
- Resolver/projection failures attach `SHADOW_ERROR` metadata and do not crash submit.
- `PolicyShadowProjection.mode` is always `shadow_only`.
- `PolicyShadowProjection.enforced` is always `False`.
- `PolicyShadowProjection` exposes no `enforce`, `apply`, `block`, `execute`, `approve`, or `submit` methods.

## Runtime Integration

Projection metadata is attached before `_append_transition(...)` on submit paths that produce or internally trace an observation:

- issuer mismatch
- input/registry contract block
- budget precheck block
- P0 policy deny
- approval auto-deny / HITL denial
- sandbox profile block
- budget charge/post-execution block
- normal command execution before trace append

The payload is stored at:

```python
ObservationEnvelope.artifacts["policy_shadow_projection"]
```

Because `ObservationEnvelope.observation_hash()` includes `artifacts`, the projection is trace-compatible metadata.

## Metadata Shape

The attached projection payload includes:

```python
{
    "enabled": True,
    "mode": "shadow_only",
    "enforced": False,
    "runtime_effective_action": "...",
    "custos_effective_action": "...",
    "alignment_status": "...",
    "mismatch_codes": [...],
    "reason_codes": [...],
    "warnings": [...],
    "violations": [...],
    "context_hash": "...",
    "registry_hash": "...",
    "resolved_policy_hash": "...",
    "runtime_snapshot_hash": "...",
    "projection_hash": "...",
}
```

On shadow failure, payloads use `alignment_status="SHADOW_ERROR"`, `custos_effective_action="WOULD_ERROR"`, `mismatch_codes=["CUSTOS_SHADOW_RESOLUTION_ERROR"]`, `mode="shadow_only"`, and `enforced=False`.
