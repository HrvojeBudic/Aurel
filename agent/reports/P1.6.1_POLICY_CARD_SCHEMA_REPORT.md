## Implemented

### New file: `schema.py`

Centralized Policy Card Schema v1 contract with:

**Schema versioning:**
- `POLICY_CARD_SCHEMA_VERSION = "1.0"`
- `SUPPORTED_POLICY_CARD_SCHEMA_VERSIONS = ("1.0",)`

**Field classifications (7 categories):**
- `POLICY_CARD_REQUIRED_FIELDS` — 6 fields: schema_version, identity, kind, status, scope, description
- `POLICY_CARD_OPTIONAL_FIELDS` — 4 fields: risk_binding, authority_binding, source, metadata
- `POLICY_CARD_FORBIDDEN_FIELDS` — 25 forbidden fields (expanded from P1.6.0's 18)
- `POLICY_CARD_CANONICAL_FIELDS` — 10 fields participating in canonical hash
- `POLICY_CARD_CONTROL_FIELDS` — kind, status, scope, schema_version
- `POLICY_CARD_GOVERNANCE_FIELDS` — risk_binding, authority_binding
- `POLICY_CARD_SOURCE_FIELDS` — source
- `POLICY_CARD_DESCRIPTIVE_FIELDS` — description, metadata
- `POLICY_CARD_IDENTITY_FIELDS` — card_id, slug, name, version, namespace
- `POLICY_CARD_RUNTIME_FUTURE_FIELDS` — 7 reserved fields (resolver, resolution, enforcement, priority, conditions, effects, actions) — NOT accepted yet

**Dangerous metadata keys:**
- `POLICY_CARD_DANGEROUS_METADATA_KEYS` — 31 keys (expanded from P1.6.0's 21)
- New additions: grant_authority, permission_grant, evidence_bypass, delegation_grant, secret_access, network_access, operator_not_required, unrestricted

**Schema functions:**
- `export_policy_card_schema()` — deterministic dict with all classifications
- `get_policy_card_schema()` — alias
- `is_supported_policy_card_schema_version()` — boolean check
- `validate_policy_card_schema_version()` — structured validation result

### `models.py` — schema_version added

`PolicyCard` dataclass now includes `schema_version: str` as its first required field.

### `validation.py` — refactored to use schema

- Imports constants from `.schema` instead of maintaining inline lists
- `DANGEROUS_TOP_LEVEL_FIELDS` = `POLICY_CARD_FORBIDDEN_FIELDS` (25 entries)
- `DANGEROUS_METADATA_KEYS` = `POLICY_CARD_DANGEROUS_METADATA_KEYS` (31 entries)
- `KNOWN_TOP_LEVEL_FIELDS` = `ALL_KNOWN_TOP_LEVEL_FIELDS` (required + optional)
- `load_policy_card_from_dict()` now requires and validates `schema_version`
- `load_policy_card_from_dict()` rejects runtime-future reserved fields
- `validate_policy_card()` checks schema_version validity

### `serialization.py` — schema_version in canonical dict

`policy_card_to_canonical_dict()` includes `"schema_version"` in output. Schema version participates in canonical hash.

### `__init__.py` — new schema exports

12 new public exports: `POLICY_CARD_SCHEMA_VERSION`, `SUPPORTED_POLICY_CARD_SCHEMA_VERSIONS`, `POLICY_CARD_REQUIRED_FIELDS`, `POLICY_CARD_OPTIONAL_FIELDS`, `POLICY_CARD_FORBIDDEN_FIELDS`, `POLICY_CARD_CANONICAL_FIELDS`, `POLICY_CARD_DANGEROUS_METADATA_KEYS`, `export_policy_card_schema`, `get_policy_card_schema`, `is_supported_policy_card_schema_version`, `validate_policy_card_schema_version`.

## Known limitations

1. **Single schema version**: Only "1.0" is supported. Migration between versions is deferred.
2. **No schema validation for nested objects**: Identity and scope sub-objects have their own field sets but no per-sub-object schema export yet.
3. **No JSON Schema generation**: The schema export produces a Python dict, not a formal JSON Schema document.
4. **Runtime-future fields are blocked**: `resolver`, `enforcement`, etc. are listed but cannot be used yet. When they become active, the schema must be updated.
