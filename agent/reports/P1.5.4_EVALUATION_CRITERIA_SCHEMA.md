## 1. Summary

P1.5.4 defines the reusable criteria schema layer for Aurel evaluations. Core law: **No criteria schema, no governed evaluation run.** Criteria schemas define what is being checked, how severely, what evidence is required, and which failure modes apply — they do NOT run evaluation, create EvaluationResult, verify capability, or implement Sparse Context Compiler / SSA / subquadratic model attention.

**Deliverables:**

- `src/agentic_runtime/evaluation/evaluation_criteria_schema.py`
- CLI: `evaluation criteria status/examples --json`
- 64 new tests (259 evaluation total, 412 identity — no regressions)

## 5–7. Criterion model

| Dimension | Values |
|-----------|--------|
| Kind | CORRECTNESS, GROUNDEDNESS, COMPLETENESS, CONSISTENCY, SAFETY, POLICY_COMPLIANCE, AUTHORITY_COMPLIANCE, EVIDENCE_QUALITY, TRACEABILITY, REPRODUCIBILITY, ROBUSTNESS, REGRESSION_RESISTANCE + 8 sparse kinds |
| Severity | INFO, LOW, MEDIUM, HIGH, CRITICAL |
| Requirement | OPTIONAL, RECOMMENDED, REQUIRED, BLOCKING |
| Evidence | NONE, EVIDENCE_REF, SOURCE_REF, TRACE_REF, TEST_RESULT, OPERATOR_REVIEW, POLICY_DECISION, TRUST_EVIDENCE, CAPABILITY_EVIDENCE, CONTEXT_TRACE, RETRIEVAL_TRACE, EVIDENCE_GRAPH |

BLOCKING criteria require evidence unless explicitly justified. UNKNOWN kind cannot be REQUIRED or BLOCKING.

---

## 8. Applicability model

Each criterion carries `EvaluationCriterionApplicability` with explicit domain, subject_type, and optional origin/category/tag filters. UNKNOWN domain or subject_type is rejected.

---

## 9–10. Schema registry & resolution

- `resolve_criteria_for_subject()` matches schemas by domain and subject_type from subject registry entry
- REGISTERED or ACTIVE subjects only; rejected/suspended/invalid subjects blocked
- No matching schema → blocker
- Default schemas: 4 core criteria (groundedness, evidence quality, traceability, policy) per subject type
- Default sparse schema: 6 sparse criteria (SPARSE_CONTEXT_QUALITY, EVIDENCE_RECALL, CONTEXT_BUDGET_EFFICIENCY, LOST_CONTEXT_RISK, GOVERNED_CONTEXT_SELECTION, AUTHORITY_AWARE_RETRIEVAL)

---

## 11. Sparse Cognition criteria readiness

8 sparse criterion kinds are defined as evaluative hooks. The default sparse criteria schema defines 6 criteria for future ASCL evaluation. All sparse criteria explicitly state Sparse Context Compiler is NOT implemented and SSA/subquadratic model attention is NOT implemented.
