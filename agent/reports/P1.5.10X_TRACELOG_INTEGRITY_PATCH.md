# P1.5.10X TraceLog Integrity Patch

Date: 2026-06-21

## Why This Patch Exists

P1.5.10X prevents future Aurel surfaces from becoming competing sources of truth. Evidence, evaluation, runtime state, memory, ledger, shell and reports all need one canonical event source before regression detection, replay, output passports and memory promotion become more serious.

The architectural rule is now explicit:

AurelTraceLog is the only canonical append-only hash-chained event source of truth. Ledger, Evidence, RuntimeState, Evaluation, Mneme, Shell and Reports are projections over AurelTraceLog.

If it is not represented in AurelTraceLog, it is not canonical.

## What Was Added

- `src/agentic_runtime/contracts/trace.py`
  - `TraceEvent`
  - `TraceEventRef`
  - `TraceBindingRef`
  - `TraceIntegrityReport`
  - deterministic canonical JSON and SHA-256 hashing helpers
  - in-memory append-only `AurelTraceLog`
  - chain verification
- `src/agentic_runtime/contracts/projections.py`
  - `ProjectionKind`
  - `ProjectionRecord`
  - projection validation and serialization helpers
- `tests/contracts/test_trace_log_integrity.py`
- `tests/contracts/test_trace_projection_contracts.py`
- `docs/adr/ADR-004-aurel-tracelog-source-of-truth.md`

## What Was Not Added

P1.5.10X does not add full AurelFlow, full AurelExec, real tool execution, real shell execution, real model execution, workflow scheduling, approval pause, retry/recovery, full Ledger migration, full Mneme memory lifecycle, Noesis, SoulIntegrityReport or Golden Thread A.

The implementation is contract-first and in-memory. Persistence and subsystem migration come later.

## Contract Rules

- AurelTraceLog is canonical.
- Everything else is a projection, view, report, index or derived artifact.
- If it is not represented in AurelTraceLog, it is not canonical.
- TraceEvent is append-only and hash-chained.
- trace_id is stable run or workflow identity, not a content-address.
- event_hash is content-addressed from canonical event content.
- ReplayReport and causal graph hashes may be content-addressable later.
- Projection records cannot claim canonical status.
- Future serious evidence, evaluation, memory, ledger, shell, report and output records must bind back to TraceEventRef.

## Tests Added

- Append creates immutable events.
- Public update/delete/remove methods are absent.
- Payload hashing uses stable sorted JSON with explicit null handling.
- Event hashes are deterministic and change when canonical content changes.
- Genesis events use `GENESIS` as previous_event_hash.
- Subsequent events chain to the previous event_hash.
- Chain verification passes valid traces and reports corrupted previous hashes, payload hashes and event hashes.
- Projection records require TraceEventRef.
- Projection records cannot claim canonical status.
- Evidence and evaluation projection records bind through TraceBindingRef.

## Seal Criteria

P1.5.10X is sealed when:

- Aurel has exactly one canonical trace source.
- Every future serious evidence, evaluation, memory, output, ledger, shell and report record can bind back to a canonical TraceEventRef.
- Trace event integrity is hash-verifiable.
- Projection ambiguity is eliminated.
