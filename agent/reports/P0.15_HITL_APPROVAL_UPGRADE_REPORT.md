approval layer with risk classes, previews, decisions, receipts, and trace
records. Runtime remains the execution authority; the approval resolver informs
when preview or explicit approval is required before a governed command runs.

## Approval architecture

- `ApprovalRequest` — structured request with tool, risk class, preview, affected paths, policy verdict
- `ApprovalDecision` — approved / denied / deferred / auto_approved / auto_denied
- `ApprovalReceipt` — durable summary of the decision for reports and trace linkage
- `ApprovalPolicy` — resolves preview/approval/auto-deny requirements from policy + tool metadata
- `build_preview()` — lightweight, redacted previews for write/patch/shell tools
- Approvers: `AutoApprover`, `ConsoleApprover`, `DenyAllApprover`, `PreviewOnlyApprover`
- `ApprovalReceiptRecord` — hash-chained trace event for every approval decision

Runtime flow:

```
Policy
  → ApprovalPolicy.resolve()
  → preview generation (if required)
  → approver decision (if required)
  → ApprovalReceipt trace append
  → execute only if approved/auto-approved
```

## Risk class behavior

| Class | Meaning | Default behavior |
|-------|---------|------------------|
| R0 | read-only / inspect | auto allow |
| R1 | safe local non-destructive | auto allow |
| R2 | reversible write | preview + explicit approval |
| R3 | external side effect (tests/exec) | preview + explicit approval |
| R4 | sensitive shell/system | preview + explicit approval + warning |
| R5 | irreversible/destructive | denied by default or two-step confirmation |

Existing `RiskLevel` values remain unchanged; `ApprovalRiskClass` maps from tool metadata, side effects, and policy risk.

## Approvers added/changed

- `AutoApprover` — risk-class aware; R5 blocked unless explicitly configured
- `ConsoleApprover` — text preview + optional two-step confirmation
- `DenyAllApprover` — safety/dry-run mode
- `PreviewOnlyApprover` — deferred after preview
- `make_approval_gate()` — factory for CLI/repo-agent modes

## Runtime integration points

- `AgenticRuntime.submit()` resolves approval requirements for all non-denied commands
- Auto-approved R0/R1 actions still produce trace receipts
- Denied/deferred commands return `HITL_DENIED` without executing
- `CommandResult` includes `approval_decision` and `approval_receipt`
- Repository agent records approval requirements in plan/dry-run and receipts during apply

## CLI usage

Approval demo:

```bash
python -m agentic_runtime.cli approve-demo --mode deny
python -m agentic_runtime.cli approve-demo --mode auto --allow-writes
```

Repository task with approval modes:

```bash
python -m agentic_runtime.cli repo-task "replace 'old' with 'new' in src/a.py" --dry-run
python -m agentic_runtime.cli repo-task "replace 'old' with 'new' in src/a.py" --approval-mode deny
python -m agentic_runtime.cli repo-task "replace 'old' with 'new' in src/a.py" --approval-mode auto --apply
```

## Known limitations

- No UI; console approver is text-only
- Preview generation is lightweight, not a full semantic diff engine
- R5 remains denied by default; two-step console confirmation is basic
- Approval resolver does not replace policy; both layers must pass
- Default sandbox remains `UnsafeLocalSandbox`
