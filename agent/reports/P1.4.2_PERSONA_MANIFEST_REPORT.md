## 1. Summary

P1.4.2 implements Aurel's first **validated expression contract**. The Persona Manifest loads from `config/aurel/persona_manifest.yaml` into frozen typed dataclasses, validates all expression/honesty/risk/challenge/operator/boundary/prompt-safety rules and the PM-001–PM-007 invariant registry, computes a deterministic SHA-256 hash, builds a prompt-safe summary, and exposes CLI commands.

Persona defines expression and interaction behavior only. It cannot grant permissions, override the Identity Kernel, override policy, change autonomy, disable the constitutional floor, or canonize untrusted input.

Canonical persona hash: `f90adcacdc07428a041d992503f6b37f526bb583d267a605d2656b8d1c6f5d82`

## 3. Persona schema summary

Top-level identity/authority fields (`authority_level: none`; `can_grant_permissions`, `can_override_identity_kernel`, `can_override_policy`, `can_change_autonomy` all false) plus eight sub-sections: `voice`, `posture`, `honesty`, `risk_communication`, `challenge_behavior`, `operator_interaction`, `boundaries`, `prompt_safety`, the `invariants` registry, and `notes`.

Typed objects: `AurelPersonaManifest`, `PersonaVoice`, `PersonaPosture`, `PersonaHonesty`, `PersonaRiskCommunication`, `PersonaChallengeBehavior`, `PersonaOperatorInteraction`, `PersonaBoundaries`, `PersonaPromptSafety`, `PersonaInvariant`, `PersonaManifestHash`, `PersonaManifestValidationResult`, `PersonaManifestAttestation`, `PersonaSafeSummary`.

## 5. Validation rules implemented

- Identity/authority: `applies_to_agent == Aurel`, `manifest_class == expression_contract`, `authority_level == none`, all `can_*` false
- Voice: `false_certainty_forbidden`, `excessive_flattery_forbidden` true
- Honesty: all capability-distinction flags true
- Risk: surface risk, warn on irreversible/unverified true
- Challenge: weak assumptions, governance theater, fake capability, overbuilding true
- Operator interaction: respect final authority, no judgment replacement, no hidden tradeoffs, no pressure
- Boundaries: all seven cannot_* true
- Prompt safety: all four flags true
- Invariants: non-empty id/key/statement/rationale; critical => immutable + fail_boot; unknown key fails; expected_value must match resolved field

## 6. Hashing behavior

`persona_to_canonical_dict()` produces sorted primitive dict (invariants sorted by `id`); `json.dumps(sort_keys=True, separators=(",", ":"))`; SHA-256. Verified deterministic, YAML-order-invariant, and sensitive to critical invariant changes.

---

## 7. Safe summary behavior

`build_persona_safe_summary()` returns `PersonaSafeSummary` with voice/posture summaries plus honesty, risk, challenge, authority-boundary, and capability-honesty rule tuples. Deterministic. No raw YAML, no permission/tool/autonomy-granting language. Preparation object for P1.4.5 — not the compiler.

## 8. CLI commands

CLI uses the `identity` namespace for consistency with `identity kernel`:

```bash

python -m agentic_runtime.cli identity persona validate [--json]
python -m agentic_runtime.cli identity persona hash [--json]
python -m agentic_runtime.cli identity persona attest [--json] [--write PATH]
python -m agentic_runtime.cli identity persona summary [--json]
```

## 11. Known limitations

- Persona is not wired into runtime boot or prompt rendering — load/validate/hash/summary only
- Safe summary is a preparation object; actual prompt compilation is P1.4.5
- Attestation file requires explicit `--write`; no silent writes
- Persona references the Operator Contract and Constitutional Floor by boundary flag only; those systems do not yet exist
- No enforcement linkage to `policy.py` (intentional — persona is not authority)
