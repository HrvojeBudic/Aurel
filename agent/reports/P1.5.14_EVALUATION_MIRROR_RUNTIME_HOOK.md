## New Enums

- `EvaluationTargetType` — `capability_evidence | evaluation_case | regression_candidate | verifier_result | trace_event`
- `EvaluationMode` — `contract | regression_seed | review_seed | capability_check`
- `EvaluationRunStatus` — `pending | running | passed | failed | needs_review | inconclusive`
- `EvaluationEventKind` — 9 typed events (`evaluation_requested` through `evaluation_needs_review`)

## New Contracts (all `@dataclass(frozen=True)`)

1. **`EvaluationTargetRef`** — target_id, target_type, source_trace_event_ref, source_event_hash, evidence_refs[], created_at. Hash must match trace ref at construction time.

2. **`EvaluationRequest`** — request_id, target_ref, requested_by, reason, evaluation_mode, required_verifier_kinds[], created_at. All required fields non-empty.

3. **`EvaluationRun`** — run_id, request_id, target_ref, status, started_at, completed_at?, emitted_event_refs[], verifier_result_refs[], evaluation_case_refs[], regression_candidate_refs[]. Terminal status requires completed_at; completed_at requires terminal status.

4. **`EvaluationEvent`** — evaluation_event_id, run_id, request_id, event_kind, source_trace_event_ref, emitted_trace_event_ref?, message, payload_hash, created_at. Binds to canonical AurelTraceLog.

5. **`EvaluationRunResult`** — run_id, request_id, status (must be terminal), summary, verifier_result_refs[], evaluation_case_refs[], regression_candidate_refs[], emitted_event_refs[], limitations[] (non-empty), errors[] (non-empty if failed), warnings[], completed_at.

## Runtime Hook

`run_evaluation(request: EvaluationRequest, *, trace_log: AurelTraceLog) -> tuple[EvaluationRunResult, EvaluationRun]`

Behavior:
1. Emits `evaluation_requested` trace event
2. Validates target (trace ref, hash, evidence_refs for capability/evaluation_case targets)
3. On validation failure: emits `evaluation_failed`, returns `EvaluationRunResult(status=failed)` with errors
4. On pass: emits `evaluation_started`, `evaluation_target_validated`, verifies trace chain
5. On chain failure: emits `evaluation_failed`, returns failed result
6. On success: emits `evaluation_completed`, returns `EvaluationRunResult(status=passed)`

## Anti-Promotion

All 5 contracts structurally prevent promotion/mutation: no `capability_promoted`, `memory_written`, `skill_created`, `reflex_created`, `policy_changed`, or similar fields exist.

EvaluationRunResult always includes non-empty limitations asserting this.

## Golden Thread A Integration

After P1.5.12 extraction and P1.5.13 normalization, `run_demo()` now:
1. Builds `EvaluationTargetRef` from capability evidence
2. Builds `EvaluationRequest` with `CAPABILITY_CHECK` mode
3. Calls `run_evaluation()`
4. Stores `evaluation_run_result` and `evaluation_run` on the harness
5. Returns `GoldenThreadAResult` with new fields: `evaluation_request_id`, `evaluation_run_id`, `evaluation_run_status`, `evaluation_result_status`, `evaluation_event_refs[]`

## Invariants Enforced

- `EvaluationTargetRef.source_event_hash` must match `source_trace_event_ref.event_hash` at construction time
- `EvaluationRunResult.limitations` always non-empty
- `EvaluationRunResult.errors` non-empty when status is failed
- `EvaluationRunResult.status` must be terminal
- `EvaluationRun.completed_at` only set when status is terminal
- `EvaluationRun` terminal status requires `completed_at`
- `EvaluationRequest.requested_by`, `reason` non-empty
- Runtime hook always emits at least 2 trace events (requested + completed/failed)
- Runtime hook never promotes capability, memory, skill, reflex, or policy

## Out of Scope

- Real verifier execution (uses existing P1.5.13 normalized verifier)
- Real evaluation case creation (uses P1.5.12 candidate extraction)
- Promotion mechanisms
- Memory/skill/reflex creation
- Policy mutation
- Full AurelFlow integration (future consumer)
