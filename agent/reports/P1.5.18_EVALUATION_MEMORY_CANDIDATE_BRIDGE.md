# P1.5.18 — Evaluation ↔ Memory Candidate Bridge

**Status:** Implemented & Sealed
**Date:** 2026-06-22
**Scope:** Evaluation, feedback, and capability outputs create MemoryCandidate records without committed memory

## Purpose

Create a safe bridge from Evaluation results, Brain-aware diagnostics, Capability claims,
Operator feedback, and Feedback processing reports to **MemoryCandidate** records.

This is explicitly NOT full Mneme (memory retrieval, consolidation, deletion, etc.)
and must NOT create committed memory, active recall, skills, reflexes, policies, or canon.

Core invariants:

```
MemoryCandidate is a CANDIDATE ONLY — never committed memory.
MemoryCandidate is NOT active recall.
MemoryCandidate does NOT create skills, reflexes, policies, or canon.
Only future governed review may convert a candidate to committed memory.
```

## Key Design Rules

1. `AurelTraceLog` is canonical source of truth
2. `MemoryCandidate` status NEVER has a "committed" value
3. Safety/policy notes must be `authority_sensitive` risk class
4. `authority_sensitive` risk class requires `needs_review` or `blocked` status
5. Bridge creates only candidates and validation reports; never commits
6. Reuses P1.5.16 `CapabilityClaim`, P1.5.17 `FeedbackProcessingReport`
7. All candidates include anti-commit language in their limitations

## What Changed from P1.5.17

| Aspect | P1.5.17 | P1.5.18 |
|--------|---------|---------|
| Golden Thread A | Claim + Report + Feedback | Claim + Report + Feedback + Memory Candidate + Bridge Report |
| Memory | Not bridged | Bridged as candidate-only |
| Committed memory | N/A | Explicitly prevented |
| Auto-commit | N/A | Explicitly blocked |

## Derivation Rules

| Input | MemoryCandidateType | Status | Risk Class |
|-------|-------------------|--------|------------|
| CREATE_MEMORY_CANDIDATE action | operator_preference | needs_review | medium |
| CORRECTION feedback | operator_correction | needs_review | medium |
| SAFETY_CONCERN feedback | safety_note | needs_review | authority_sensitive |
| POLICY_CONCERN feedback | policy_note | needs_review | authority_sensitive |
| Capability with limitations | limitation_note | candidate | low |
| Any capability claim | capability_lesson | candidate | low |

## Golden Thread A

Default demo: after feedback processing, the bridge creates a `capability_lesson`
MemoryCandidate from the `context_verified` claim. Status: `candidate`, risk: `low`.
`memory_committed` is always `False`.

## Hard Invariants Verified

- No "committed" status in MemoryCandidateStatus enum
- AUTHORITY_SENSITIVE requires needs_review or blocked
- SENSITIVE requires needs_review or blocked
- Safety/policy notes cannot be low risk
- Candidates with candidate/needs_review status require evidence_links
- Bridge report never references skill/reflex/policy/canon creation
- Every MemoryCandidate must include anti-commit language in limitations
- Invalid validation reports require non-empty blocked_reasons
