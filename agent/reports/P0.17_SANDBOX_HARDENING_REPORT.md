enforcement, path boundaries, execution limits, structured violations, trace
records, and diagnostics — without claiming fake Docker/Bubblewrap security when
backends are unavailable.

Core law preserved: **Entity proposes. Runtime disposes.** Tool access is not
machine access.

## Sandbox architecture

```
SandboxProfile (capabilities + limits)
  → SandboxPolicy (tool/path checks)
  → ProfiledSandbox (FS/exec boundary wrapper)
  → Tool Bus execute() (capability gate)
  → Runtime.submit() (pre-exec sandbox gate)
  → SandboxViolationRecord (trace)
  → SandboxDiagnostics (status CLI)
```

### Contracts added

- `SandboxProfile`, `SandboxProfileName`, `SandboxPolicy`
- `SandboxExecutionLimits`, `SandboxExecutionContext`
- `SandboxDiagnostics`, `SandboxViolation`, `SandboxDecision`
- `SandboxCapabilityMap`, `ProfiledSandbox`
- Path helpers: `resolve_workspace_path`, `is_path_allowed`, `is_secret_like_path`, `enforce_path_policy`

## Sandbox profiles

| Profile | Read | Write | Exec | Network | Secrets | Unsafe |
|---------|------|-------|------|---------|---------|--------|
| `no_exec_readonly` | yes | no | no | no | no | no |
| `restricted_local` | yes | yes | yes (timeout) | no* | no | no |
| `unsafe_local_demo` | yes | yes | yes | not blocked* | no | **yes** |
| `docker` | yes | yes | yes | no | no | no (if available) |
| `bubblewrap` | yes | yes | yes | no | no | no (if available) |

\*Unsafe local backend cannot technically block network; diagnostics state this honestly.

Docker/Bubblewrap profiles raise `SandboxUnavailableError` when backends are not
installed — no silent downgrade to unsafe mode.

## Security boundaries enforced

- Paths must resolve under `workspace_root` (traversal + symlink escape rejected)
- Secret-like paths (`.env`, credentials, keys) blocked by default
- Write/exec denied when profile disallows
- Execution timeout capped by profile `max_timeout_seconds`
- Output capped by `max_output_bytes` (existing mechanism)
- Environment scrubbed for unsafe local subprocesses (`_scrubbed_env`)
- Secrets not passed to tools by default (`allow_secrets=False`)

## Runtime integration

`AgenticRuntime.submit()` checks `SandboxPolicy` after approval and before budget
execution charge. Violations return structured `SANDBOX_VIOLATION` results and
append `SandboxViolationRecord` to the trace — tool handlers never run.

## Tool Bus integration

`ToolBus.execute()` performs a second policy check and returns structured
`ToolExecutionResult` with `error.code=sandbox_violation` when denied.

## Repo agent integration

- Default apply profile: `restricted_local`
- Dry-run / plan-only: `no_exec_readonly`
- `RepoTaskRequest.sandbox_profile` configurable
- `CodeTaskReport.sandbox_profile` and `sandbox_violations` populated

## Praxis integration

- `PraxisExperience.sandbox_profile` captured from repo reports
- Sandbox-denied executions produce failure/diagnostic candidates only (no success memory)

## Known limitations

- `restricted_local` still uses `UnsafeLocalSandbox` backend — not a hard security boundary
- Network isolation requires Docker/Bubblewrap; unsafe local documents the gap
- No network/browser tools implemented (denied by policy if requested)
- Profiled path allowlists are prefix-based; complex glob rules are minimal
- Repo agent context builder still reads local files directly (bounded, pre-plan)
