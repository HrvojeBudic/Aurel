# P0.20 — First Real Coding Agent Demo Report

**Date:** 2026-06-17  
**Status:** **PASS**

## 1. Summary

P0.20 is the first proof milestone. It runs the controlled P0.19 demo harness end-to-end through the **public, governed path** and generates honest evidence that the full governed coding-agent loop works:

```
objective → bounded repo context → explicit plan → approval preview
→ governed patch → tests → repair loop (available) → trace
→ sandbox summary → praxis candidate/report → final evidence report
```

The `buggy_calculator` scenario produced a real failing test, the agent generated a plan before patching, the patch went through Runtime → Tool Bus → Approval → Sandbox, the final test passed, and all subsystem summaries plus evidence artifacts were produced. No fake success; no tests weakened.

## 2. Scenario used

`buggy_calculator` (from `src/agentic_runtime/demo_harness.py`):

- `calculator.py` — bug: `add(a, b)` returns `a - b`
- `test_calculator.py` — `assert add(2, 3) == 5`
- `pyproject.toml` — minimal metadata
- `allowed_paths`: `calculator.py`, `test_calculator.py`, `pyproject.toml`
- `max_files_changed`: 1
- `sandbox_profile`: `restricted_local`

## 13. What worked

- Plan-first behavior recorded before patch

- Sandbox profile recorded, network/secrets denied, zero violations

## 14. What failed or remained limited

- Planner remains deterministic (`replace '…' with '…'` pattern), not LLM-driven — see P0.21 recommendation
- Single-file arithmetic scenario; not representative of multi-file repo work
- `restricted_local` uses `UnsafeLocalSandbox` — not a production security boundary
- Repair loop was not exercised (first patch passed); it is available and tested separately
- Two suite-wide tests (`test_timeout_kills_long_running_command`, `test_run_shell_timeout_is_enforced`) fail only inside restricted CI sandboxes that block nested subprocesses; they pass in normal environments (documented in `TESTS.md`)
