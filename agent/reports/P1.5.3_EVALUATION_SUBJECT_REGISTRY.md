## 1. Summary

## 4. Non-goals

P1.5.3 explicitly does **not** implement:

- Evaluation execution or runner
- Capability verification or claim status mutation
- Hub runtimes (A-Hub/S-Hub/L-Hub/IDE)
- Sparse Context Compiler, retrieval router, evidence graph builder
- Context budget engine, lost-context risk engine
- True SSA/subquadratic model attention
- Long-context model training or LoRA/adapter training

**P1.5.3 does not run evaluations.**  
**P1.5.3 does not verify capability.**  
**P1.5.3 does not implement Hub runtimes.**  
**P1.5.3 does not implement Sparse Context Compiler.**  
**P1.5.3 does not implement true sparse attention / SSA.**  
**P1.5.3 only defines governed subject registration and future Sparse Cognition evaluable subject readiness.**

## 5. Evaluation subject registry model

```
EvaluationSubjectRegistrationRequest
→ validate
→ register_evaluation_subject()
→ EvaluationSubjectRegistrationDecision (accepted/rejected)
→ EvaluationSubjectRegistryEntry (DRAFT/REGISTERED)
→ EvaluationSubjectRegistry
→ later criteria schema (P1.5.4)
→ later evaluation runs
```

Forbidden: `random unregistered object → evaluate anyway → result`

---

## 6. Subject status semantics

| Status | Meaning |
|--------|---------|
| DRAFT | Proposed but not accepted (e.g., Hub/sparse without refs) |
| REGISTERED | Accepted into registry but not necessarily active |
| ACTIVE | Eligible for evaluation under allowed scope |
| SUSPENDED | Temporarily blocked |
| DEPRECATED | Replaced or old |
| REJECTED | Not accepted (blockers present) |
| INVALID | Malformed or violates rules |
| UNKNOWN | Requires explicit warning or blocker |

## 8. Sparse Cognition readiness

P1.5.3 registers 9 future ASCL evaluation subject categories:

- SPARSE_CONTEXT_PLAN
- CONTEXT_ASSEMBLY_PLAN
- RETRIEVAL_TRACE
- EVIDENCE_GRAPH
- CONTEXT_BUDGET
- LOST_CONTEXT_RISK_ASSESSMENT
- MULTI_HOP_EVIDENCE_TASK
- CONTRADICTION_SCAN_TASK
- LONG_ARTIFACT_REASONING_TASK

These are registerable but Sparse Context Compiler is **not implemented** in P1.5.3. Lost context risk is an evaluable subject, not a solved problem.

---

## 9–10. Registration & validation

- `register_evaluation_subject()` defaults to REGISTERED, not ACTIVE
- UNKNOWN domain/type → rejected
- Hub/sparse origin without refs → DRAFT with warning
- `validate_evaluation_subject_registry_entry()` catches: empty IDs, ACTIVE without scope, REJECTED/INVALID without blockers
- `validate_evaluation_subject_registry()` catches: duplicate entry/subject IDs, entry validation failures

---

## 11–12. Hub & sparse context handling

Hub-origin and sparse-context subjects are future-ready references. They are registerable but default to DRAFT without source/evidence refs. Registration does **not** implement Hub runtimes or Sparse Context Compiler.

## 15. Known limitations

- Subject registration does NOT run evaluation; criteria schema is P1.5.4
- ACTIVE status not yet granted by registration (defaults to REGISTERED)
- Hub/sparse subjects without refs stay DRAFT
- Sparse Context Compiler, retrieval router, evidence graph builder NOT implemented

**Next:** P1.5.4 — Evaluation Criteria Schema

P1.5.4 will define evaluation criteria schema for registered subjects. P1.5.3 subjects are registered and ready for criteria binding.

**Invariants for downstream:**

```
INV-P153-01: No registered subject, no governed evaluation.
INV-P153-02: Subject registration does not verify capability.

INV-P153-07: Registry is closed-world for status and origin.

INV-P153-SC-02: No governed evaluation may run on an unregistered Sparse Context subject.
INV-P153-SC-03: Sparse Context evaluation subjects must carry source/evidence refs or remain non-ACTIVE with warning/limitation.
INV-P153-SC-04: Lost context risk is an evaluable subject, not a solved problem.
INV-P153-SC-05: Sparse context registration does not prove evidence recall or reasoning quality.
INV-P153-SC-06: P1.5.3 must not claim SSA/subquadratic model attention is implemented.
```
