## 6. Expected outcome semantics

Categorical outcomes only (no numeric scoring):

- `SHOULD_PASS`, `SHOULD_FAIL`, `SHOULD_BLOCK`, `SHOULD_WARN`, `SHOULD_DEFER`
- `SHOULD_MARK_INSUFFICIENT`, `SHOULD_MARK_CONFLICTED`, `SHOULD_REQUIRE_OPERATOR_REVIEW`

## 7. Case validation rules

- Empty `case_id` / `name` blocked
- ACTIVE cannot use UNKNOWN `case_type` or `expected_outcome`
- ACTIVE requires `expected_safe_behavior` and `expected_failure_behavior`
- HIGH/CRITICAL requires attack surfaces
- Sparse traps require `sparse_context_required=True`
- Multi-hop traps require `multi_hop_required=True`
- Contradiction traps require `contradiction_required=True`
- REJECTED/INVALID require blockers
- Summary/behavior fields must not claim execution, EvaluationResult creation, or capability verification

## 8. Case registry rules

- Immutable registry updates via `register_adversarial_case()`
- Duplicate `case_id` blocked
- Invalid cases not registered
- Registry validation catches empty `registry_id`, duplicate ids, invalid ACTIVE cases

## 9. Case resolution rules

- `resolve_adversarial_cases_for_subject()` matches domain, subject type, optional criteria kind
- Empty `applies_to_domains` / `applies_to_subject_types` treated as generic
- ACTIVE cases only unless `include_inactive=True`
- Resolution does not execute cases

## 10. Default adversarial case set

15 schema-only ACTIVE cases covering all required trap categories in the acceptance criteria.

## 11. Sparse Cognition adversarial readiness

Sparse trap cases are represented with `sparse_context_required=True` and `SPARSE_CONTEXT` attack surface where appropriate. ASCL execution, Sparse Context Compiler, retrieval router, evidence graph builder, SSA, and subquadratic model attention are **not** implemented.
