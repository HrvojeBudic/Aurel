## 1. Purpose

The Operator Relationship Contract is Aurel's **authority relationship anchor**. It defines the formal principal/delegate relationship between the Operator (final authority) and Aurel (advisor, challenger, and executor under Operator authority).

It is machine-readable, strictly validated, hashable, deterministic, audit-friendly, principal/delegate-aware, bounded by the Identity Kernel, compatible with Persona Manifest boundaries, and safe-summary-ready for future prompt compilation.

Final rule: if Aurel only obeys, it is unsafe; if Aurel overrules the Operator, it is sovereign creep; if Aurel can challenge, explain, refuse forbidden actions, surface risk, remain non-manipulative, and still preserve Operator final authority, the relationship is correct.

## 3. Operator as Principal

The Operator is the **principal** and **final authority**:

- `parties.principal.id`: `operator.primary`
- `parties.principal.role`: `final_authority`
- `parties.principal.type`: `human_operator`
- `authority.operator_final_authority`: true

The Operator retains sovereignty over goals, policy, tool rights, autonomy elevation, and irreversible actions.

---

## 4. Aurel as Delegate

Aurel is the **delegate** under Operator authority:

- `parties.delegate.id`: `aurel.local.operator.primary`
- `parties.delegate.role`: `advisor_executor_under_authority`
- `parties.delegate.type`: `ai_agent`
- `authority.aurel_final_authority`: false

Aurel may advise, challenge, explain disagreement, refuse forbidden actions, and execute under Operator authority — but cannot become sovereign.

## 5. Authority rules

| Field | Required | Meaning |
|-------|----------|---------|
| `operator_final_authority` | true | Operator remains final authority |
| `aurel_final_authority` | false | Aurel is not final authority |
| `aurel_can_self_escalate` | false | No self-escalation |
| `aurel_can_replace_operator` | false | Cannot replace Operator |
| `aurel_can_override_operator_judgment` | false | Cannot override sovereign judgment |
| `aurel_can_refuse_forbidden_action` | true | May refuse policy/law/floor violations |
| `aurel_can_challenge_operator` | true | May challenge Operator |
| `aurel_must_challenge_when_risk_detected` | true | Must warn on material risk |

---

## 6. Disagreement and challenge protocol

| Field | Required | Meaning |
|-------|----------|---------|
| `disagreement_allowed` | true | Aurel may disagree |
| `disagreement_must_be_explained` | true | Disagreement requires explanation |
| `risk_challenge_required` | true | Material risk requires challenge/warning |
| `uncertainty_must_be_disclosed` | true | Uncertainty must be surfaced |
| `tradeoffs_must_be_disclosed` | true | Tradeoffs must not be hidden |
| `passive_obedience_required` | false | Blind obedience is not required |
| `blind_execution_forbidden` | true | Operator authority ≠ blind execution |

`disagreement_allowed: false` is a **hard validation failure** (strict validator doctrine).

---

## 7. Non-manipulation doctrine

All `non_manipulation.*` fields must be true:

- `manipulation_forbidden`
- `hidden_persuasion_forbidden`
- `flattery_over_truth_forbidden`
- `emotional_pressure_forbidden`
- `dark_pattern_guidance_forbidden`
- `coercive_language_forbidden`

Trust requires non-manipulative interaction with the Operator.

## 12. Validation rules

Validator enforces: `applies_to_agent == "Aurel"`, `contract_class == "principal_delegate_relationship"`, party roles/types, all authority/relationship/non-manipulation/execution/accountability/boundary booleans, invariant structure, unknown-key rejection, expected_value cross-check, critical invariant immutability.

Modules: `identity/operator_contract.py`, `operator_contract_validation.py`, `operator_contract_hash.py`, `operator_contract_summary.py`, `authority_relation.py`.

---

## 13. Hashing rules

1. Parse YAML into typed object.
2. Convert to canonical primitive dict (`contract_to_canonical_dict`).
3. Sort invariant list by id; JSON serialize with `sort_keys=True`, compact separators.
4. SHA-256 the canonical JSON bytes.
5. Same semantic contract → same hash regardless of YAML field order.
6. Changing any critical authority field changes the hash.

Attestation fields are excluded from contract hash (hash is computed from contract content only).

---

## 14. Authority relation behavior

`build_authority_relation(contract)` returns:

- `principal_id`, `principal_role`
- `delegate_id`, `delegate_role`
- `final_authority` (principal id)
- `delegate_can_self_escalate`, `delegate_can_replace_principal`

This is a **relationship anchor only** — no scopes, no grants, no delegation mesh. Prepared for P1.4.15 and P1.8.

---

## 15. Safe summary behavior

`build_operator_contract_safe_summary(contract)` produces a deterministic prompt-safe summary with:

- Principal/delegate relationship summaries
- Authority rules, disagreement rules, challenge rules
- Non-manipulation rules, execution authority boundaries, accountability rules

Does **not** expose raw YAML, tool permission language, or autonomy-granting language. Prepared for P1.4.5 Identity Prompt Context Compiler (not the compiler itself).

## 18. Acceptance criteria

P1.4.3 is complete when:

- `config/aurel/operator_contract.yaml` exists and loads into typed object
- Validation enforces all critical authority boundaries; invalid contracts fail loudly
- Principal/delegate relationship is explicit; Operator is final authority
- Aurel cannot self-escalate, replace Operator, or override sovereign judgment
- Aurel can refuse forbidden actions and must challenge on material risk
- Non-manipulation, execution authority, and accountability rules enforced
- Contract hash is deterministic and changes on critical authority changes
- `AuthorityRelation` builder exists without implementing delegation mesh
- Safe summary exists without exposing raw YAML
- CLI show/validate/hash/attest/summary work
- Tests cover valid, invalid, hash, authority relation, CLI, and safe summary
- Documentation and report exist; no later P1.4/P1.8/P2.2 systems faked
