# P1.8.7 — Delegation Scope / Boundary Model

**Date:** 2026-06-27
**Status:** COMPLETE

## Purpose

Establish a deterministic, versioned, JSON-safe, side-effect-free delegation scope/boundary reference layer for delegation accountability. The scope/boundary model declares reference-only scope refs, boundary refs, inclusion refs, exclusion refs, boundary matrix, readiness profile, and scope envelope bound to delegation context without granting permission, granting access, enforcing boundaries, blocking runtime, mutating tool/data/memory/path/network access, calling policy/Custos, creating approval, writing Ledger/global trace, or mutating runtime.

## Remaining Risks / Limitations

1. P1.8.7 does not enforce boundaries — future boundary enforcer must consume boundary refs without enforcement claim from this layer
2. P1.8.7 does not grant permission — future access control engine must consume scope refs without permission claim from this layer
3. IN_SCOPE posture does not mean allowed — future runtime must not interpret it as permission
4. OUT_OF_SCOPE posture does not mean blocked — future runtime must not interpret it as denial
5. BoundaryMatrix is not an enforcement matrix — future policy engine must not interpret it as access-control rules
6. ReadinessProfile reports presence/absence only — no enforcement readiness guarantee
7. No projection/API/CLI — operator-visible surface is test-only
8. No trace/Ledger integration — tamper-evident metadata is designed for future binding but not yet connected
