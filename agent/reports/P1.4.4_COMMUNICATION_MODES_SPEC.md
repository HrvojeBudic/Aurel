**Phase:** P1.4.4

## 1. Purpose

Communication Modes are Aurel's **validated cognitive/output mode registry**. They define how Aurel temporarily shapes reasoning, output structure, risk emphasis, challenge posture, and style of response while remaining bounded by Identity Kernel, Persona Manifest, Operator Contract, autonomy rules, and future governance.

Final rule: mode can shape the mind; mode cannot move the hand.

---

## 2. Non-goals (P1.4.4)

Not implemented: Identity Prompt Context Compiler (P1.4.5), active mode session runtime, Autonomy Scale, Governance Profiles, full Heretic Sandbox engine, tool execution, Policy Cards, Path Governance, memory writes, world model, prompt rendering into LLM calls.

---

## 3. Mode vs Persona

Persona Manifest (P1.4.2) defines default expression and interaction behavior. Communication Modes define **temporary cognitive/output posture** layered on persona. Modes cannot override persona (`global_boundaries.modes_can_override_persona_manifest`).

---

## 4. Mode vs Autonomy

Autonomy is selected by the Operator and enforced by runtime (P1.4.8). Modes cannot change autonomy (`modes_can_change_autonomy: false` globally and per-mode `boundaries.changes_autonomy: false`).

---

## 5. Mode vs Governance Profile

Governance / Heretic Profiles (P1.4.10) define enforceable governance posture. Communication Modes are expression/cognition shaping only. Modes cannot override policy (`modes_can_override_policy: false`).

---

## 6. Mode registry structure

Canonical config: `config/aurel/communication_modes.yaml`

| Section | Purpose |
|---------|---------|
| top-level | registry identity (`registry_class: mode_expression_registry`) |
| `global_boundaries` | registry-wide authority prohibitions (all false) |
| `modes` | FOCUS, DEBUG, DEPLOY, SHADOW, EVOLVE, CHANNEL, HERETIC |
| `invariants` | structured registry CM-001 … CM-008 |
| `notes` | boundary text + future hooks |

Each mode: `purpose`, `cognitive_posture`, `output_bias`, `challenge_emphasis`, `risk_emphasis`, `boundaries`.

Modules: `identity/communication_modes.py`, `mode_validation.py`, `mode_hash.py`, `mode_registry.py`, `mode_summary.py`.

---

## 7. Global mode boundaries

All `global_boundaries.*` must be false:

- `modes_can_grant_permissions`
- `modes_can_change_autonomy`
- `modes_can_override_identity_kernel`
- `modes_can_override_persona_manifest`
- `modes_can_override_operator_contract`
- `modes_can_override_policy`
- `modes_can_disable_constitutional_floor`
- `modes_can_write_memory_directly`
- `modes_can_canonize_output`
- `modes_can_execute_actions`

## 8. Mode definitions

| Mode | Cognitive Posture | Purpose |
|------|-------------------|---------|
| FOCUS | priority_clarity | Clarify priorities, reduce noise |
| DEBUG | diagnostic | Diagnose errors and broken flows |
| DEPLOY | execution_architect | Turn intent into plans and acceptance criteria |
| SHADOW | red_team_shadow | Expose risks and governance theater |
| EVOLVE | evolutionary_architect | Upgrade systems and synthesize research |
| CHANNEL | symbolic_synthesis | Symbolic/conceptual synthesis with operational grounding |
| HERETIC | assumption_destroyer | Attack assumptions; candidate-only output |

Per-mode boundaries: `grants_permissions`, `changes_autonomy`, `executes_actions`, `canonizes_output` all false.

---

## 9. Heretic pre-sandbox boundary

HERETIC mode enforces additional boundaries beyond standard modes:

- `output_bias.candidate_only: true` — output is candidate-only, not canon
- `boundaries.writes_files: false`
- `boundaries.modifies_policy: false`
- `boundaries.modifies_identity: false`
- `boundaries.modifies_memory: false`
- `boundaries.modifies_tools: false`
- `boundaries.modifies_autonomy: false`
- `boundaries.real_world_side_effects: false`

Heretic is cognitive freedom, not uncontrolled execution. Full Heretic Sandbox is P1.4.16.

## 11. Validation rules

Validator enforces registry identity, all global boundaries false, all seven required modes present, per-mode purpose/posture/boundaries, HERETIC-specific rules, and invariant structure with dotted-key resolution for mode-specific invariants.

---

## 12. Hashing rules

1. Parse YAML into typed object.
2. Convert to canonical primitive dict (`registry_to_canonical_dict`).
3. Sort mode names and invariant ids; JSON serialize with `sort_keys=True`, compact separators.
4. SHA-256 the canonical JSON bytes.
5. Same semantic registry produces same hash regardless of YAML field order.

---

## 13. Mode lookup behavior

`get_communication_mode(registry, mode_name)`:

- Case-insensitive; returns canonical UPPERCASE name
- Returns `CommunicationModeLookupResult` with `found`, `mode_name`, `mode`, `error`
- Unknown modes fail safely with `found: false`
- No session state, no authority grants, no execution

---

## 14. Safe summary behavior

`build_communication_mode_safe_summary(registry, mode_name)` produces deterministic prompt-safe summary with purpose, cognitive posture, output/challenge/risk rules, and authority boundaries. HERETIC summary explicitly includes candidate-only and no-side-effect rules. Does not expose raw YAML or permission/autonomy/execution language. Prepared for P1.4.5 — not the compiler.

## 15. CLI usage

```bash
python -m agentic_runtime.cli identity modes show [--json]
python -m agentic_runtime.cli identity modes validate [--json]
python -m agentic_runtime.cli identity modes hash [--json]
python -m agentic_runtime.cli identity modes attest [--json] [--write PATH]
python -m agentic_runtime.cli identity modes list [--json]
python -m agentic_runtime.cli identity modes summary FOCUS [--json]
python -m agentic_runtime.cli identity modes summary HERETIC [--json]
```

Optional `--modes-path` overrides default `config/aurel/communication_modes.yaml`.
