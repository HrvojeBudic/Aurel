# P1.5.13 — Verifier Normalization with Limitations

## Purpose

Normalizes all verifier outputs into one canonical `VerifierResult` shape so Aurel cannot create verified capability evidence, evaluation cases, regression candidates, memory candidates, skill candidates, or future promotions from raw or ambiguous verifier output.

Every verifier result used by Aurel is now:
- trace-bound
- evidence-bound
- reasoned
- confidence-scored
- limitation-bound
- normalized

## What changed from P1.5.12

P1.5.12 proved: verified/failed outcomes can become future evaluation candidates.

P1.5.13 now proves: those outcomes depend on normalized verifier results, not raw or ambiguous judgment. This is the main defense against fake capability learning.

## VerifierKind

```text
DETERMINISTIC — deterministic condition check
OPERATOR_REVIEW — human/operator review (evidence, not automatic truth)
POLICY_CHECK — policy compliance check (policy only, not task correctness)
LLM_JUDGE_STUB — stub LLM judge (never calls a real model)
CONTEXT_ADEQUACY — context adequacy check
EVIDENCE_INTEGRITY — structural evidence integrity check
```

## VerifierResult v2

Existing `VerifierResult` was upgraded with:
- `verifier_kind: VerifierKind` — what kind of verification produced this result
- `normalized_from: str | None` — audit trail to raw input
- `created_at: str` — creation timestamp

Hard validation rules (all enforced via `__post_init__`):
- `limitations[]` must be non-empty for every VerifierResult
- `reason` must be non-empty
- `confidence` must be between 0.0 and 1.0
- `status=pass` requires `evidence_refs[]` non-empty
- Serious VerifierResult requires `source_trace_event_ref`

## VerifierNormalizationReport

```text
normalization_id
verifier_kind
raw_input_ref?
normalized_verifier_result_ref?
normalization_status: normalized | failed | needs_review
reason
warnings[]
errors[]
created_at
```

Makes verifier normalization auditable and inspectable.

## VerifierAdapter / normalizers

Six stub verifiers, all producing `(VerifierNormalizationReport, VerifierResult)`:

| Normalizer | Purpose | Key rule |
|---|---|---|
| `normalize_deterministic_result` | Deterministic condition pass/fail | `condition_passed=True → PASS` |
| `normalize_operator_review` | Human operator review | Approval is evidence, not truth |
| `normalize_policy_check` | Policy compliance | Pass must NOT claim task correctness |
| `normalize_llm_judge_stub` | LLM-as-judge shape, no real model | Never calls a real LLM |
| `normalize_context_adequacy` | Context adequacy → VerifierResult | `adequate→pass`, `partial→needs_review`, `insufficient→fail`, `unsafe→fail` |
| `normalize_evidence_integrity` | Structural evidence integrity | Checks integrity, not truth of claim |

## Stub verifiers

- **DeterministicVerifierStub**: Condition-based pass/fail with 1.0 confidence
- **OperatorReviewVerifierStub**: Human review with 0.85 confidence; states it does not generalize
- **PolicyCheckVerifierStub**: Policy compliance check; explicitly states it's not task correctness
- **LLMJudgeVerifierStub**: Stub judgment at 0.7 confidence; no API keys, no network calls, states it's not production-grade
- **ContextAdequacyVerifierStub**: Maps ContextAdequacyReport status to verifier status
- **EvidenceIntegrityVerifierStub**: Checks structural evidence (exists, has trace ref, content_hash exists, source_event_hash matches)

## Mandatory limitations

Every VerifierResult has non-empty `limitations[]`. Each stub verifier declares its own limitations explicitly.

## Updated Golden Thread A

Golden Thread A now routes verifier creation through the normalization layer:

```text
EvidenceRef
→ EvidenceIntegrityVerifierStub (normalizer)
→ VerifierNormalizationReport
→ VerifierResult (evidence_integrity, pass, limitations, evidence_refs, trace_ref)
→ CapabilityEvidenceRecord
→ EvaluationCase (candidate, positive)
```

`GoldenThreadAResult` now includes:
- `verifier_kind`
- `normalization_report_id`
- `normalization_status`
