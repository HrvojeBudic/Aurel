# P1.5.11A Golden Thread A Minimal Contract Harness

Date: 2026-06-22

## Purpose

P1.5.11A proves the first minimal vertical evidence path over canonical AurelTraceLog.

The patch establishes that verified capability evidence cannot appear unless it is bound to:

- canonical TraceEventRef
- at least one EvidenceRef
- VerifierResult
- verifier status `pass`
- non-empty verifier limitations
- non-empty capability limitations

## Vertical Path

Golden Thread A runs:

```text
Intent
→ Context
→ Policy
→ Lease
→ Stub Exec
→ Trace
→ Evidence
→ Verifier
→ Capability Evidence
```

The harness is deterministic. It appends one `stub_execution_completed` event to canonical `AurelTraceLog`, then creates an `EvidenceRef`, `VerifierResult`, and verified `CapabilityEvidenceRecord` bound to that event.

## Invariants

- AurelTraceLog remains the only canonical source of truth.
- EvidenceRef must bind to TraceEventRef.
- EvidenceRef cannot claim canonical status.
- VerifierResult limitations must be non-empty.
- VerifierResult `pass` requires evidence refs.
- VerifierResult confidence must be between `0.0` and `1.0`.
- Verified CapabilityEvidenceRecord must be created by the verified factory.
- Verified CapabilityEvidenceRecord requires TraceEventRef.
- Verified CapabilityEvidenceRecord requires at least one EvidenceRef.
- Verified CapabilityEvidenceRecord requires VerifierResult.
- Verified CapabilityEvidenceRecord requires verifier status `pass`.
- Verified CapabilityEvidenceRecord requires non-empty capability limitations.

## Explicitly Out of Scope

P1.5.11A does not implement full AurelFlow Runtime, real AurelExec, real ExecutionLease, ObjectRef plane, workflow scheduling, approval pause, retry/recovery, tool execution, shell execution, LLM execution, full Ledger migration, full Mneme memory lifecycle, Noesis, SoulIntegrityReport, full OperatorFeedback, or CapabilityClaimRegistry.

Operator feedback alone cannot promote capability evidence to `verified`.

## Seal Criteria

P1.5.11A is sealed when:

- GoldenThreadAHarness exists.
- `run_demo()` produces a deterministic Intent → Context → Policy → Lease → Stub Exec → Trace → Evidence → Verifier → Capability Evidence path.
- Stub execution binds to a canonical AurelTraceLog event.
- EvidenceRef binds to TraceEventRef.
- VerifierResult includes limitations.
- CapabilityEvidenceRecord becomes verified only under hard invariants.
- Negative tests prove verified capability cannot exist without trace, evidence, verifier, limitations, or verifier pass.
