## 1. Summary

P1.4.1 implements Aurel's first **machine-readable identity trust anchor**. The Identity Kernel loads from `config/aurel/identity_kernel.yaml` into frozen typed dataclasses, validates critical identity invariants (IK-001–IK-008), computes a deterministic SHA-256 hash, and exposes CLI commands for show, validate, hash, and attest.

Identity Kernel defines **immutable trust boundaries** — not persona, not autonomy, not tool authority.

Canonical kernel hash: `9f17c9861d01a04bde4568174a082d52fde4f44c9bc2e316c231924555935c57`

## 3. Kernel schema summary

Top-level `identity_kernel` sections:

- **Core:** `schema_version`, `name`, `class`, `primary_operator`, `final_authority`, `local_first`
- **immutables:** six boolean identity laws
- **development_allowed:** six competence-growth flags
- **development_forbidden:** four sovereignty-violation flags (all must be `true`)
- **invariants:** structured registry IK-001–IK-008
- **notes:** boundary text and future hooks

Typed objects: `AurelIdentityKernel`, `IdentityImmutables`, `DevelopmentAllowed`, `DevelopmentForbidden`, `IdentityInvariant`, `IdentityKernelHash`, `IdentityKernelValidationResult`, `IdentityKernelAttestation`.

## 5. Validation rules implemented

- Core identity field constraints (`Aurel`, `sovereign_personal_agent`, `single_human_operator`, `operator`, `local_first: true`)
- All immutables and development_forbidden values
- Invariant id/key/statement/rationale non-empty
- Unknown invariant keys fail
- Critical invariants: `mutable: false`, `violation_action: fail_boot`
- `expected_value` must match resolved kernel field

---

## 6. Hashing behavior

1. `kernel_to_canonical_dict()` — primitive dict with sorted invariant list by `id`
2. `json.dumps(..., sort_keys=True, separators=(",", ":"))`
3. SHA-256 hex digest

Verified: same semantic kernel → same hash; YAML top-level key reorder does not change hash; statement change changes hash.

## 10. Known limitations

- Kernel is not wired into runtime boot or `build_runtime()` — read/validate only
- No Identity Integrity Guard enforcement at runtime (P1.4.14)
- Attestation file not auto-written; requires explicit `--write`
- Invariant keys map only to `immutables` and `development_forbidden` fields
- Persona, Operator Contract, and Autonomy layers remain separate
