## 1. Implementation Summary

P1.6.9 delivers the Sandbox Policy Card Model, a frozen-dataclass-based representation of sandboxing constraints expressed as a declarative policy card. The implementation spans three new files and two modified files, establishing a complete, serializable, and semantically evaluable model for sandbox policy cards.

### Key Artifacts

- **7 Enums** define a closed-world vocabulary for sandbox configuration.
- **11 Frozen Dataclasses** model all state as immutable, hashable objects.
- **`evaluate_sandbox_policy_decision()`** produces a deterministic `SandboxPolicyDecision` from a card and input — semantic resolution only, no runtime enforcement.
- **Canonical Serialization** (`sandbox_policy_card_to_canonical_dict()`, `serialize_sandbox_policy_card_canonical()`, `compute_sandbox_policy_card_hash()`) ensures deterministic output via sorted keys.
- **Schema Versioning** anchored at `"1.0"` with a `SUPPORTED_VERSIONS` set.
- **Dangerous Field/Key Rejection** guards against forbidden fields and metadata injection.

## 2. Key Design Decisions

### 2.1 Frozen Dataclasses for All Model Objects

Every model object is a `@dataclass(frozen=True)`, ensuring immutability, hashability, and structural equality. This eliminates an entire class of bugs related to accidental mutation of policy state and enables safe use as dictionary keys and set members.

**Model classes:**

| Dataclass | Role |
|-----------|------|
| `SandboxBackendRule` | Declares which sandbox backend (e.g., `BUBBLEWRAP`, `DOCKER`) is required |
| `SandboxFilesystemScopeRule` | Defines filesystem visibility: `FULL`, `READ_ONLY`, `NO_FILESYSTEM` |
| `SandboxEgressRule` | Controls outbound network access: `ALLOW_ALL`, `ALLOW_LISTED`, `NO_EGRESS` |
| `SandboxCommandClassRule` | Maps command classes (e.g., `ShellCommand`, `FileWrite`, `NetworkCall`) to per-rule decisions |
| `RiskTierSandboxMapping` | Associates a risk tier with a sandbox policy card |
| `SandboxPolicyCard` | Top-level container: backend, filesystem, egress, command classes, metadata |
| `SandboxPolicyDecision` | Resolver-ready output: the aggregate decision after evaluating a card against input |
| `SandboxPolicyDecisionInput` | Input structure for decision evaluation |
| `SandboxPolicyViolation` | Represents a hard violation that blocks execution |
| `SandboxPolicyWarning` | Represents a soft warning that does not block execution |
| `SandboxValidationIssue` | Captures a single validation problem during construction |
| `SandboxValidationResult` | Aggregates all validation issues found |

### 2.2 Closed-World Vocabulary via 7 Enums

Seven enums enforce a closed-world vocabulary, preventing invalid or ambiguous values from entering the model at any point.

| Enum | Values | Purpose |
|------|--------|---------|
| `SandboxBackend` | `NONE`, `BUBBLEWRAP`, `DOCKER` | Declared sandbox backend technology |
| `FilesystemScope` | `FULL`, `READ_ONLY`, `NO_FILESYSTEM` | Filesystem visibility policy |
| `EgressPolicy` | `ALLOW_ALL`, `ALLOW_LISTED`, `NO_EGRESS` | Network egress policy |
| `CommandClass` | `ShellCommand`, `FileRead`, `FileWrite`, `FileDelete`, `NetworkCall`, `ProcessSpawn`, `SecretAccess`, `Unknown`, `Destructive`, `All` | Classified command types |
| `SandboxCommandDecision` | `ALLOW`, `DENY`, `REQUIRE_APPROVAL` | Per-rule decision for a command class |
| `ApprovalRequirement` | `NONE`, `OPERATOR`, `OPERATOR_WITH_REASON` | Human-in-the-loop escalation level |

**Name collision resolution:** `SandboxCommandDecision` is the per-rule enum. The aggregate resolver output is the separate `SandboxPolicyDecision` dataclass. This avoids the semantic confusion that would arise from overloading a single symbol for both per-rule and aggregate decisions.

### 2.3 Deny-by-Default Posture at Every Level

A deny-by-default security posture is enforced at every policy dimension:

- **Filesystem:** Default is `NO_FILESYSTEM` — the agent sees no filesystem unless explicitly granted.
- **Egress:** Default is `NO_EGRESS` — no outbound network access unless explicitly allowed.
- **Commands:** `Unknown`, `Destructive`, and `SecretAccess` command classes are denied by default. Explicit allow-listing is required for any command class.

This ensures that omission of a policy dimension never results in an overly permissive posture.

### 2.4 Resolver-Ready Decision Evaluation

The function `evaluate_sandbox_policy_decision(card: SandboxPolicyCard, input: SandboxPolicyDecisionInput) -> SandboxPolicyDecision` takes a card and an input context and produces a deterministic `SandboxPolicyDecision`. 

**Key properties:**

- **Semantic only** — no runtime enforcement. The decision is a data structure, not an action.
- **Deterministic** — given the same card and input, the same decision is always produced.
- **Aggregate** — combines backend, filesystem, egress, and command-class checks into a single decision with violations and warnings.
- **Deny-by-default** — any command class not explicitly listed in the card's command class rules is denied.

This design cleanly separates the policy model (P1.6.9) from the runtime resolver (P1.6.10), enabling shadow-mode evaluation and dry-run analysis before enforcement is activated.

### 2.5 Canonical Serialization

Three functions provide deterministic, canonical serialization:

- `sandbox_policy_card_to_canonical_dict(card: SandboxPolicyCard) -> dict` — converts a card to a canonical dictionary with sorted keys at every nesting level.
- `serialize_sandbox_policy_card_canonical(card: SandboxPolicyCard) -> str` — JSON-serializes the canonical dict with `sort_keys=True`, `indent=None`, and `separators=(",", ":")` for a compact, deterministic string.
- `compute_sandbox_policy_card_hash(card: SandboxPolicyCard) -> str` — computes a SHA-256 hex digest over the canonical serialization, enabling content-addressable storage and tamper detection.

All serialization paths use sorted keys, guaranteeing that structurally equivalent cards produce identical serialized forms and identical hashes regardless of insertion order.

### 2.6 Schema Versioning

The schema is versioned at `"1.0"` with a `SUPPORTED_VERSIONS: Set[str] = {"1.0"}` constant in `sandbox_schema.py`. This enables forward-compatible parsing: a future runtime can read a card, check its version against the supported set, and either process it or reject it with a clear version-mismatch error.

### 2.7 Dangerous Field/Key Rejection

During validation (via `validate_sandbox_policy_card()`), the model rejects:

- **Forbidden fields** — keys that do not belong in a sandbox policy card (e.g., fields from other policy card families inadvertently merged).
- **Metadata injection** — unrecognized keys in the metadata section are flagged as validation issues.

This defense-in-depth measure prevents accidental or malicious blending of policy card families and ensures metadata hygiene.

## 3. Non-Goals Satisfied

The following are explicitly **not** addressed by P1.6.9 and remain deferred to later phases:

| Non-Goal | Deferred To | Rationale |
|----------|-------------|-----------|
| Runtime enforcement of sandbox decisions | P1.6.10+ | P1.6.9 is a pure model layer; enforcement lives in the Custos resolver and runtime hooks |
| Modification of `AgenticRuntime.submit()` | P1.6.10+ | Submission interception is a runtime concern, not a model concern |
| Custos resolver integration | P1.6.10 | The resolver will consume `SandboxPolicyDecision` output from this model |
| Docker/Bubblewrap backend implementation | Future infrastructure track | Backend execution is orthogonal to policy modeling |
| Actual sandbox execution or container management | Future infrastructure track | P1.6.9 models constraints; it does not enforce them |

This clean separation ensures the policy card model can be fully tested, hashed, serialized, and reasoned about without any dependency on a running sandbox environment.

## 6. Readiness for P1.6.10

P1.6.9 is complete and provides all primitives required by P1.6.10 (Custos v0 Policy Runtime Resolver / Shadow Mode):

- **`SandboxPolicyCard`** — the declarative input to the resolver.
- **`SandboxPolicyDecisionInput`** — the runtime context fed into evaluation.
- **`evaluate_sandbox_policy_decision()`** — the deterministic evaluation function that produces `SandboxPolicyDecision`.
- **`SandboxPolicyDecision`** — the structured output containing violations, warnings, and the aggregate decision.
- **Canonical serialization + hashing** — enables shadow-mode comparison: compute the hash of the card used at evaluation time, store it alongside the decision, and later verify that the same card was applied.

The Custos resolver (P1.6.10) can now consume these primitives to implement shadow-mode evaluation, dry-run analysis, and eventually enforcement — all without modifying the model layer.
