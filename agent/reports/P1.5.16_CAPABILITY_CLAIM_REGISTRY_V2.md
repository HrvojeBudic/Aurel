# P1.5.16 — Capability Claim Registry v2

**Status:** Implemented & Sealed  
**Date:** 2026-06-22  
**Scope:** Anti-overclaim documentation layer over Evaluation Mirror (P1.5.14/15)

## Purpose

Introduces a governed system that controls what Aurel may claim about its own
capabilities. Ensures Aurel never overclaims — it cannot claim capability beyond
evidence. Every positive capability claim must be:

- **Trace-bound** (bound to canonical AurelTraceLog)
- **Evidence-bound** (bound to CapabilityEvidenceRecord)
- **Verifier-bound** (bound to VerifierResult)
- **Context-bound** (bound to ContextAdequacyReport)
- **Limitation-bound** (requires KnownLimit entries on serious claims)
- **Scope-bound** (requires CapabilityClaimScope)
- **Status-controlled** (candidate → decision → claim, never direct promotion)

## Key Design Rules

1. `AurelTraceLog` is canonical source of truth — claims are projections
2. Reuses `GoldenThreadA` and `BrainAwareEvaluationContext` (P1.5.15)
3. No second capability truth source — no memory, no skill promotion, no policy mutation
4. No open-domain cognition or LLM-based claim generation
5. Deterministic status derivation from evaluation results

## Core Invariant

**Aurel may not claim capability beyond evidence.** A single Golden Thread A run
produces `context_verified`, not `verified` or `verified_candidate`.

### Derivation Logic (`derive_capability_claim_candidate`)

Ordered rules for status determination:

1. UNSAFE context or CRITICAL risk → `failed`
2. Verifier FAILED or EvaluationRunResult FAILED → `failed`
3. Context INSUFFICIENT → `failed`
4. Evidence weak/moderate/none → `weakly_supported`
5. EvaluationRunResult INCONCLUSIVE or NEEDS_REVIEW → `experimental`
6. Verifier INCONCLUSIVE → `experimental`
7. Context PARTIAL → `experimental`
8. Default Golden Thread A (PASSED + ADEQUATE + PASS verifier + STRONG evidence) → `context_verified`

**Never derived by default:** `verified` or `verified_candidate`

## Anti-Promotion Enforcement

P1.5.16 does NOT create, write, or mutate:
- Skills (no skill creation)
- Memory (no memory writes)
- Reflexes (no reflex creation)
- Policy (no policy mutations)
- Capability promotion

All claim objects verified to have zero promotion-related field names.

## Golden Thread A Behavior

After P1.5.16, `GoldenThreadAHarness.run_demo()`:
1. Creates capability evidence (P1.5.13)
2. Runs evaluation through runtime hook (P1.5.14)
3. Produces brain-aware diagnostics (P1.5.15)
4. **Derives a `CapabilityClaimCandidate` with `context_verified` status** (P1.5.16)
5. **Accepts the candidate via `CapabilityClaimDecision`** (P1.5.16)
6. **Creates a `CapabilityClaim` with evidence link and limits** (P1.5.16)
7. **Builds a `CapabilityClaimReport` with honest scope/limitation warnings** (P1.5.16)

The claim is `context_verified` only — NOT `verified` or `verified_candidate`.
